# 2026-08-24 — Ulanzi 마켓플레이스 첫 게재, 그리고 태그를 걸어야만 드러나는 결함

### 문제

Ulanzi가 `1.0.3`을 게재했다 — 이 스토어가 실어준 최초의 AgentDeck 빌드이고, 제출
17일 만이다. 그런데 그 시점의 게시본은 이미 레포보다 17일 뒤처져 있었고, 포털을
직접 읽어보니 갭이 셋이었다.

1. **하위 카테고리가 `Office`**. 옆에 놓인 에이전트 플러그인들(울란지 1st-party
   `Codex Micro`, `Claude Code Usage`)은 전부 `AI`다. AI 코딩 에이전트가 주제의
   전부인 플러그인이, 그것을 찾는 사람들과 다른 칸에 정리돼 있었다.
2. **7개 언어 카피가 전부 한 문장**. 영문 기준 Summary 51/300, Detailed
   introduction 51/1000. `marketplace/ulanzi/LISTING.md`에 7개 언어 정본이 1.0.0
   때부터 있었는데 게시본엔 들어가 있지 않았다 — 새로 쓸 것 없이 채우기만 하면
   되는 상태였다.
3. **같은 버전 번호에 다른 내용**. 게시본은 D200/D200H·D200H 전용 매니페스트인데
   레포의 `plugin-ulanzi`는 `ulanzi-v1.0.3`보다 3커밋 앞서 `Devices:["D200H",
   "D200X"]`를 선언하고 있었다.

### 해결

포털이 그 사이 개편됐고, 그게 이번 라운드를 싸게 만들었다. 게시본 카드의 연필이
이제 *Create review version*을 연다 — "새 버전을 심사에 넣되 게시본은 그대로 살아
있다". 심사 중 플러그인을 건드리지 않는다는 기존 방침은 **심사 레코드가 유일한
레코드였을 때의 규칙**이라 게시된 작품에는 더 이상 적용되지 않는다.

`1.0.4`를 그 경로로 제출했다. D200X 키패드(이슈 #174 — 두 기기가 Studio에 같은
14키를 노출하고 레이아웃은 모델명이 아니라 사용자가 배치한 키 수로 자기 크기를
정하므로 코드 변경 없이 선언만), 게시본이 그릴 수 없던 Kiro/Kiro IDE/Antigravity
마크와 답할 수 있는 OpenClaw 승인, de/es/pt 로케일 3종 추가, D200X 문구가 빠져
있던 zh_HK 정정, 카테고리 AI, 7개 언어 카피 복원, 그리고 미디어 재생성.

배너는 리터칭이 아니라 렌더러에서 다시 뽑았다. 데크 픽스처를 12세션 → 10세션으로
줄여 **6개 에이전트가 한 페이지에 다 보이게** 했다 — 12개일 때 Kiro 2개가
`agentTypeRank` 때문에 2페이지로 밀려서, 광고하는 6종 중 2종이 배너에서 조용히
빠져 있었다. 하드웨어 사진은 합성 없이 **살아 있는 윗줄 5키로 크롭**했다: 게시본
배너는 전체 면을 잡았는데 촬영 당시 14키 중 9키가 미할당이라, 실물을 증명하는
유일한 자산이 "먼지 낀 어두운 데크"로 읽혔다.

`ulanzi-v1.0.4` 태그는 두 번 빨갛게 났다. `npx --yes esbuild` →
`sh: 1: esbuild: not found`.

### 핵심 설계 결정

- **릴리스 경로의 도구는 이름이 아니라 패키지 매니저의 fetch 경로로 부른다.**
  esbuild는 이 레포의 선언된 의존성이 아니고 vite의 transitive로만 존재한다. pnpm
  워크스페이스 안에서 `npx`는 그 사본을 보고 "이미 설치됨"으로 판정해 설치를
  건너뛴 뒤, bin을 못 찾아(pnpm은 transitive bin을 링크하지 않는다)
  `sh -c esbuild`로 흘러간다. dev 머신은 hoisted bin이 남아 있어 **영원히
  초록**이라, 2026-08-09 초록 이후 태그를 걸 때까지 잠복했다. CLAUDE.md의 esptool
  핀과 같은 규칙이고 같은 실패 모드다 — 태그 시점에 터진다.
- **추측으로 고치면 태그를 한 번 더 태운다.** 첫 수정은 `npx --yes esbuild@0.28.2`로
  버전만 박았고 아무 것도 바뀌지 않았다 — npx의 "이미 설치됐나" 검사는 버전 지정과
  무관하게 매칭된다. 두 번째에는 CI가 보는 조건을 재현했다(fresh clone →
  `pnpm install --frozen-lockfile` → `pnpm build` → 스크립트 실행). 이 재현 절차를
  스크립트 주석에 박아 두었다.
- **검증은 3환경 해시 대조로 닫는다.** dev 머신 / 클린 클론 / 발행된 릴리스 에셋의
  `plugin/app.js`가 모두 `f76886a8…`이고, 이는 마켓플레이스에 올린 아카이브와
  동일하다. 핀이 "그 빌드를 만든 컴파일러"라는 진술이 실측으로 닫힌다.
- **포털은 지원 기기를 전부 켜 놓는다 — `Dial` 포함.** 선택/비선택이 육안으로
  구분되지 않아(둘 다 분홍) DOM 클래스로 읽어야 한다. 끄지 않았으면 엔코더 미구현
  기기를 지원한다고 광고할 뻔했다. 반대로 ZIP을 올리면 매니페스트를 파싱해 버전은
  자동으로 채운다.
- **앱 캡처는 하드웨어 사진을 대체하지 못한다(실측).** Ulanzi Studio는 창이 고정
  크기라 데크 프리뷰가 네이티브 508×308px다. 1920 배너에서 banner-01이 쓰는
  폭(1382px)을 채우려면 2.7× 업스케일이고, 같은 화면을 벡터에서 뽑는 banner-01이
  이미 존재한다. 캡처는 정보를 더하지 않고 해상도만 잃는다.
