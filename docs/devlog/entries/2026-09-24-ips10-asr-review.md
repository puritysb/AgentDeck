# 2026-09-24 — Review IPS10 recognition separately from endpointing

Reviewed the installed whisper.cpp large-v3-turbo backend (`ko-KR`, local warm server) without changing production configuration. The retained synthetic original, earlier IPS10 microphone recording, wake-only fixture and a longer Korean fixture were compared. These are diagnostic examples, not a representative human accuracy benchmark; the retained microphone file predates the latest firmware.

The original short instruction transcribed correctly in 0.53 s: “다른 작업은 하지 말고 음성 연결 확인이라고만 답해줘.” The microphone recording returned “다른 작업은 하지 말고 음성연결 고민이라고만 하죠.” in 0.50 s. Both are 16 kHz mono, with no full-scale clipping or significant DC offset. This implicates the acoustic/capture path as one contributor but does not isolate room echo, bandwidth loss, distance, or sample discontinuities. The smaller installed base model was substantially worse on that microphone file. Leading trims and beam search had already failed to improve it in the preceding investigation.

A stronger false-command reproduction used newly generated six-second fixtures: digital silence returned “감사합니다.” (0.484 s), and a 120 ms start tone plus deterministic low-level noise returned “3. 아이안아” (0.602 s). The current host accepts a nonempty transcript without an independent speech-presence gate. These controlled fixtures demonstrate hallucination exposure; their frequency in real user conditions is not measured.

An isolated temporary warm server with the official Silero v5.1.2 VAD model returned empty text for those two fixtures in 0.052 / 0.049 s. The original instruction stayed correct (0.582 s), while the earlier microphone fixture remained wrong and changed to “자립 작업은 하지 말고 음성 연결 속이라고만 가주죠.” (0.525 s). VAD segmentation is therefore not an established accuracy improvement. Evaluate speech-presence gating while retaining the full utterance before adopting aggressive segmentation. Wake-only still transcribes as “오픈클록”; VAD cannot decide whether speech is a command or just the invocation.

The existing Apple on-device path could not participate in the comparison: the helper aborted under TCC because its responsible app lacked `NSSpeechRecognitionUsageDescription`, as confirmed by the crash report. This is an integration failure, not evidence about Apple's recognition accuracy. No privacy permission or production backend was changed. All temporary helper/server processes were stopped.

Decision: large-v3-turbo remains a reasonable candidate for local latency, but the current end-to-end recognition pipeline is not yet adequately validated for automatic command submission. Prioritize a speech-presence guard, current-device human recordings with known references, quiet/noisy and near/far conditions, and command accuracy plus false-submission rates. Compare a higher-accuracy model on that same corpus before replacing the engine. Diagnostics, machine-readable outputs and scripts are under `diagnostics/asr-review/` (ignored).
