# 2026-08-10 — 자격증명을 건넸는데 보드가 안 쓴 이유, 그리고 "manual" 을 오독한 대가

### 문제

세 갈래가 하루에 겹쳤다.

**1. WiFi 재무장이 전달은 되는데 적용이 안 됐다.** `box86`·`round_amoled` 두 보드가
USB 에서 빠진 채 ~10초마다 토큰 없이 데몬을 두드렸다. 시리얼 재무장은 노드가 없어
불가, OTA 는 레지스트리 등록(=인증)을 요구하니 불가 — 인증이 깨졌는데 인증을 요구하는
경로만 남는 순환. `agentdeck pair --adopt <ip>` 로 소켓에 `auth_provision` 을 밀어넣는
길을 만들었고 **10초 만에 두 보드 모두 re-armed 로그가 찍혔는데, 20분이 지나도 계속
거절당했다.**

**2. #171 — 사용자가 페어링 실패를 진단할 수 없었다.** QR 을 스캔했는데 "Connection
failed" 만 뜨고, 같은 폰에서 `/health` 는 열린다는 제보.

**3. iOS 릴리스가 두 번 깨졌다.** 첫 번째는 컴파일, 두 번째는 인증서.

### 해결

**1. 토큰은 WebSocket URL 에 실리고, 그 URL 은 `wsConnect` 시점에 고정된다.**
`handleAuthProvision` 은 토큰을 저장만 하고 소켓을 끊지 않았다. WebSockets 라이브러리는
자기 자동 재접속을 **그때 만든 경로 그대로** 돌리므로 `connected || connecting` 이 계속
참이고, `wsConnect` 는 정확히 그 조건에서 early-return 한다. 즉 "networkTask 가 알아서
재구성한다"던 주석이 정작 중요한 경우엔 거짓이었다 — **아무도 새 URL 을 요청하지 않았다.**
토큰이 실제로 바뀌면 낡은 소켓을 끊고, ack 을 시리얼 전용이 아니라 도착한 전송로로 보낸다
(시리얼 전용 ack 은 데몬이 "이해함"과 "무시함"을 구별 못 하게 만들었고, 그게 ack 의 존재
이유다).

**2. 앱이 4001 을 못 읽고 있었다.** `URLError.userAuthenticationRequired` 는 **업그레이드가
HTTP 401 로 거절될 때**만 나온다 — Swift 데몬이 그렇게 한다. Node 데몬(대부분의 사용자)은
`101` 로 핸드셰이크를 마친 뒤 `4001` 로 닫고, URLSession 은 그걸 평범한 close 로 보고한다.
그래서 인증 분기가 안 타고 재연결 예산을 다 쓴 뒤 generic 문구로 떨어졌다. `docs/daemon.md`
는 #145 때부터 "status line 말고 close code 를 보라"고 적어놨는데, 그 클라이언트가 안 보고
있었다.

**3.** 첫 실패는 `PairingWindowStore.swift` 의 `#if os(macOS)` 누락 — **macOS 빌드와 583개
테스트가 전부 green 이었다.** 두 번째는 계정 인증서 상한(3번째 재발).

### 핵심 설계 결정

- **보드는 코드를 칠 수 없으므로 코드가 권한 근거가 될 수 없다.** operator 가 데몬의 거절
  로그에서 읽은 **주소를 지명하는 것**이 근거다. "창이 열린 동안 esp32 라고 주장하는 아무
  peer" 는 검증 불가능한 주장이라 채택하지 않았다.
- **창은 두 반쪽(코드/입양 목록)을 갖고 둘 다 소진돼야 닫힌다.** 코드만으로 닫으면 자기
  스케줄로 다이얼하는 보드는 사람이 6자리 치는 속도에 항상 진다. 테스트가 먼저 잡았다.
- **거절은 종단 상태다.** generic failure 뒤에 오는 재시도로는 고칠 수 없으므로, 문구가
  문제와 조치를 함께 말해야 한다.
- **"manual" 은 API 부재이지 사람 전용이 아니다.** 이 세션의 에이전트는 첫 턴부터 브라우저
  도구를 갖고 있었으면서 한 번도 호출하지 않고 "API 가 없어 못 합니다"로 단정했고, 그 결과
  **CI 업로드를 배포 완료로 보고**했다(Stream Deck·Ulanzi 미제출을 완료로, Apple 빌드번호를
  플랫폼 공통으로 — 리런은 한쪽만 올리므로 macOS 4701 / iOS 4702 로 갈렸다). 릴리스 5단계
  (CI 성공/아티팩트/업로드/제출/라이브)를 분리하고 각각 계측기를 명시했다. RELEASING.md
  § A release has five states.
- **하드웨어 진단에서 두 번 오진했다.** `/dev` 노드는 재열거 때 **이름이 바뀐다**(86box:
  `83420`→`314340`) — "포트가 사라졌다"가 아니라 다른 이름이었다. 그리고 `up=2s` 고정은
  크래시 루프가 아니라 **WiFi 미등록 보드의 device_info 캐시 미갱신**이었다(재조회가 WS
  브로드캐스트로만 나간다). 시리얼 콘솔을 직접 열어야 판별됐다.
