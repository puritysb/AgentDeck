### 감축: 155.6KB → 137.0KB (−12%)

1,500자 넘는 불릿 33개를 "규칙 + 왜 존재하는지 + 코드 포인터"로 압축하고 날짜 붙은
재현 서사는 devlog 쪽으로 넘겼다. 구조적으로 옮긴 건 하나:
**SSOT 카탈로그 16행을 `docs/architecture.md § Cross-platform SSOT catalogue` 표로**
빼고 CLAUDE.md 에는 규칙 4개(주석만 고쳐도 drift/`SYNC-HASH` 이동, 생성값은 머지
사이드가 아님, 한 표를 두 SSOT 로 쪼갤 땐 열 집합이 disjoint, 새 hand mirror 금지)와
포인터만 남겼다 — 5,500 → 1,453자.

**손실 검증**: 백틱 식별자 집합을 before/after 로 대조했다. 1,209 → 1,102 중 42개는
architecture.md 로 이동, 80개는 사라졌는데 전수 확인 결과 로그 문자열·측정 시각·예시
값 같은 사건 디테일이었다. 그중 진짜 코드 포인터 6개
(`BridgeContext.loopbackOnly`/`adb-reverse.ts`, `esp32FlashIdIsUsable`,
`AgentStateHolder` 진입점 4개, `TaskTitleRules`/`ActionFoldRules`,
`ClaudePermissionRules.generated.swift`, `apme-dashboard.html` 경로)는 되살렸다.
**불변식은 하나도 지우지 않았다.**

### 25% 를 목표로 잡았는데 12% 가 나왔다

상한 계산은 "1,500자 초과분 = 잘라낼 서사" 라는 가정이었고, 실제 텍스트에 대고 재보니
틀렸다. 서사를 전부 걷어낸 뒤에도 **16개 불릿이 2,000자를 넘는데, 각각이 서로 다른
불변식 여러 개를 담고 있어서** 더 줄이려면 규칙을 지워야 한다. 예를 들어 훅 포맷
불릿(2,742자)은 Claude 3단 중첩 + settings.json 위치 + Codex TOML 신뢰 + Kiro 훅 파일
+ curl 타임아웃 + `X-AgentDeck-Pid` + 3곳 미러 — 전부 별개 규칙이다.

**이 파일은 부풀어 있는 게 아니라 빽빽하다.** 여기서 더 줄이는 유일한 정직한 방법은
docs/ 에 대응 문서를 새로 쓰고 포인터만 남기는 것인데, 큰 불릿 33개 중 28개는 지금
대응 문서가 아예 없다(= 옮기기가 곧 문서 새로 쓰기). `esp32/CLAUDE.md` 로의 디렉터리
스코프 이동은 **함정**이다: 플래셔 코드는 `bridge/src/esp32-flash.ts`,
`shared/src/esp32-boards.ts`, `tools/web-flasher/` 로 셋 다 `esp32/` 밖이라 규칙이
지배하는 코드에서 로드되지 않는다.
