# 2026-11-02 — USB vendor review needs the real registry size and XIAO identity

### Measurement

While reviewing PR #641 in an isolated checkout, a read-only
`ioreg -r -c IOUSBHostDevice -l -w0` returned **1,148,133 bytes** on the maintainer
Mac. That exceeds Node's default 1 MiB `exec` output limit. Keeping that limit
would turn a successful registry read into the unknown-vendor fallback and
silently disable the new exclusion on this machine. The registry command now
has an explicit bounded 8 MiB budget; other serial commands retain their existing
limit and timeout.

The same registry named one connected device **Seeed Studio XIAO ESP32S3**, vendor
`0x2886`, product `0x0056`. The initial three-vendor list would reject this supported
board. The shared vendor policy includes Seeed alongside Espressif, WCH and
Silicon Labs, and the board generator emits Swift's membership. Drift is checked
against generated bytes, rather than comparing two separately hardcoded test
expectations.

### Evidence boundary

Only the I/O Registry was read. No serial port was opened, no board was reset,
and no firmware or installed daemon was changed for this measurement. The local
registry resolved supported WCH, Espressif and Seeed devices. CP210x and the
reporter's LG display were unavailable here; fixtures cover those vendor choices.
A known foreign vendor is refused before opening; a failed or missing lookup
remains unknown and retains pattern-based discovery for compatibility. The gate
identifies vendor membership, not proof that every device from an admitted vendor
runs AgentDeck firmware.
