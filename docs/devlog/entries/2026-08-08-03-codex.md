# 2026-08-08 — Codex 무료 티어: 죽은 게이지를 회수해 공간으로 되돌리다

### 문제

Codex 구독이 끝났는데 모든 표면이 여전히 **ChatGPT Plus 시절의 주간 94%** 를 그리고
있었다. `auth.json` 은 `chatgpt_plan_type: "free"` 인데 rollout 스냅샷은
`plan_type: "plus"`, `resets_at` 은 8/11 — **미래**다. 그래서 기존 두 신선도 축이
모두 무력했다: `stale` 은 창이 끝나야 켜지고(주간 창은 최대 7일 미래),
`capturedAt` 은 흐리게만 만든다. "오래된 값"이 아니라 **남의 값**인데 그걸 말할 수
있는 신호가 없었다.

그 결과가 좁은 패널에서 공간 낭비로 나타났다.

- **iDotMatrix 32×32**: 텔레메트리 레일 4행을 무조건 예약. 없는 제공자 자리는
  검은 띠 — 32행 패널에서 한 행이 화면의 3%다.
- **Pixoo64**: Codex 밴드 7행이 유령 수치를 들고 상주.
- **Stream Deck / D200H**: Codex 타일이 키를 점유. 반면 실제로 구속력을 갖는
  per-model 주간 캡(Fable)은 D200H 에 **아예 도달한 적이 없었다** —
  `state-store.ts` 가 `scopedLimits` 를 레이아웃 입력에 넣지 않아서
  `buildUsageTiles` 의 scoped 분기는 죽은 코드였다.
- **Swift 데몬 단독**: Claude 쿼터 경로가 없으니 Codex 가 유일한 게이지인데,
  그게 비면 메뉴바가 빈 "RATE LIMITS" 헤더만 그렸다.

### 해결

**세 번째 축을 만들었다 — "이건 누구 숫자인가".** `codexSnapshotMatchesAccountPlan`
(`shared/src/format-utils.ts`, `pnpm generate-codex-freshness-rules` 로 Swift
`CodexPlanRules` 미러). 스냅샷의 `plan_type` 과 계정 티어가 다르면 그 창은 오래된
게 아니라 **void** 다. 양쪽 중 하나라도 모르면 **match** — 부재는 정보 없음이지 실
데이터를 지울 근거가 아니다(API 키 설치는 계정 티어가 없다).

두 생산자에서 화해시킨다: `normalizeCodexRateLimits`(Node) /
`codexRateLimitsPayload`(Swift). void 는 키를 빼는 게 아니라 **창 없는
`{ planType }` 로 명시 송출** — 클라이언트가 retain-on-absent 로 머지하므로 키를
빼면 은퇴한 게이지가 영원히 박힌다(`usageStale` 래치와 같은 모양).

회수한 공간:

- **iDotMatrix**: 존재하는 레일만, **하단 정렬**. Claude 전용이면 2행, 아무것도
  없으면 0행 — 나머지는 수조로 돌아간다.
- **Pixoo64**: 제공자 밴드가 통째로 사라져 수조가 7행을 되찾는다.
- **Stream Deck 키패드 / D200H**: Codex 가 비운 키를 scoped 캡이 가져간다.
  중재자는 공유 술어 `scopedLimitClaimsUsageKey` — **active** 캡은 구속하는 한도이므로
  Codex 앞에 서고, **inactive** 캡은 Codex 가 남긴 키에만 앉는다(살아 있는 창을
  절대 밀어내지 않는다). D200H 는 `scopedLimits` 배선도 함께 고쳤다.
- **SD+ E3**: 대체가 애매한 다이얼은 그대로 두되, 문구만 정직하게
  `Free tier · no quota`(기존 "No Codex usage" 는 읽기 실패처럼 보였다).

**소비자 규칙**: 블록의 존재가 아니라 **창의 존재**를 봐야 한다. `codexRateLimits
!= nil` 로 게이트하던 두 곳이 새 모양에서 깨졌다 — ControlTowerPanel 이 빈 헤더를
그렸고, `esp32-serial` 이 어떤 제공자도 채우기 전에 -1 센티널 프레임을 보드로 밀었다.
