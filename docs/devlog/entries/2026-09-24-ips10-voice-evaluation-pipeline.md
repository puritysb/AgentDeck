# 2026-09-24 — Evaluate and gate IPS10 speech before command recognition

Added an offline evaluator that uses the production transcription backend and shared wake-word stripping, without dispatching commands. It records per-case transcripts, normalized character edits, command presence, operational errors and latency. An optional acceptance gate exits unsuccessfully on false accepts, rejected positive cases or operational errors. Private audio remains in ignored diagnostics. Instructions: [voice evaluation](bridge/tools/VOICE-EVALUATION.md).

Added explicitly configured `voice.whisperVadCli` and `voice.whisperVadModel` paths for a local Silero speech-presence check before both warm-server ASR and CLI fallback. It preserves the complete original WAV: it does not splice speech segments or trim consonants. Silence is rejected; malformed output, unavailable models and the five-second deadline fail as operational errors rather than bypassing the check. Apple remains the default backend when none is selected.

The controlled corpus contains 12 cases: three clean synthetic Korean commands, three current IPS10 speaker-to-microphone captures, one older microphone fixture, wake-only, silence, two noise levels and cue-plus-noise. Baseline large-v3-turbo accepted four of five negative cases; the presence-gated variant accepted zero. All seven positive cases remained accepted, with identical transcripts and normalized character error ratio 8/92. In the final repeat, median latency was 450 ms baseline and 524 ms gated across all cases; this mixed median is not command-only latency. The current three microphone recordings had two exact command matches and one error (“오늘 날짜를 알려줘” became “오늘 날짜는 안여줘”). These are synthetic/acoustic examples, not a human accuracy estimate.

Full large-v3-q5_0 was also evaluated separately: 7/92 character edits, 705 ms mixed median, four false accepts, and the same current microphone command still wrong. It is not selected for deployment. Running both warm models concurrently caused the VAD executable to time out during Metal-library initialization; stopping the extra server restored normal VAD operation. This is a reproducible operational limitation of that comparison setup, not evidence of recognition accuracy. The temporary server was stopped; production keeps the turbo model.

Two additional wake-only acoustic trials on the installed firmware cancelled after 6001 / 6003 ms without uploading speech. The capture harness returned empty ASR text so benchmark recordings never dispatched an agent command; settings, serial leases and Mac output volume were restored afterward.

Validation: build, typecheck, 4683 tests passed (two skipped), protocol generation without drift, token mirrors synchronized. Built-checkout design lint retained 171 existing findings. Remaining work for recognition quality is a reference-labelled human corpus covering soft speech, pauses and near/far conditions; the presence filter addresses false submission, not word accuracy.
