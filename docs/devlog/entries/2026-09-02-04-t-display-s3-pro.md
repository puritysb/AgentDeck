# 2026-09-02 — T-Display-S3-Pro 재부팅 루프: 가드는 있었지만 이 붕괴의 리셋 사유를 몰랐다

### 문제

t_display_pro가 "USB 연결 → 곧바로 WiFi 전환 → 꺼짐 → 켜짐"을 반복. 데몬
로그에는 이 포트의 시리얼 재등록(토큰 재무장)이 10~30초 간격으로 284회
찍혀 있었다.

### 해결

원인은 코드가 아니라 **전원 경로**였고, 세 가지 실측이 그것을 확정한다.
`/dev/cu.usbmodem21301`을 60초 샘플링하면 USB 노드가 **열거 자체에서**
사라진다(최장 생존 21초) — 앱 레벨 재접속이 아니라 SoC의 USB 주변장치가
꺼진다는 뜻. 보드 자가보고의 리셋 사유는 `poweron`(code=1)으로, 브라운아웃도
워치독도 아닌 **완전한 전원 소실 후 재기동**이다. macOS의 USB 과전류 이벤트는
0건이라 Mac이 포트를 끊는 것도 아니다. 그리고 **배터리 스위치를 켜자 즉시
멈췄다** — 90초 연속 노드 탈락 0초, 재등록 0회, `wifiRadioParked=true`로
USB-primary 정상 상태. 셀이 순간 부하를 흡수하는 벌크 커패시터 역할을 한 것.

이 보드는 SY6970 PMU + 470mAh 셀을 쓰는데 **펌웨어에 SY6970 설정 코드가 전혀
없다**(T-Embed의 BQ25896만 관리). 공장 기본값의 입력 전류 한도 안에서
디스플레이 + native CDC 부하를 배터리 없이 버티지 못한 것이다.

### 핵심 설계 결정

**루프 차단 가드는 있었는데 이 붕괴 유형에는 한 번도 발동하지 않았다.**
펌웨어는 `esp_reset_reason() == ESP_RST_BROWNOUT`이면 그 부팅에서 WiFi
auto-join을 금지한다("retrying is what turned one dip into a self-sustaining
reboot loop"). 그런데 PMU가 전원을 통째로 끊는 이 유형은 칩에 **POWERON**으로
보고되므로, 매 부팅이 "정상 첫 부팅"으로 보여 가드가 조용히 비켜간다. 25초
deferred WiFi join도 매 리셋마다 처음부터 카운트돼 radio 전류 스파이크를
얹었고, 이것이 사용자 눈에 "USB → WiFi → 꺼짐" 순서로 보인 정체다.
**리셋 사유는 붕괴의 원인을 분류하지 못한다** — 같은 물리 현상이 전원 경로의
어느 지점에서 끊기느냐에 따라 BROWNOUT도 POWERON도 된다.

후속 2건은 미착수로 남긴다: ① 루프 가드를 리셋 사유 대신 **NVS 부트
카운터**로(poweron은 RTC 메모리도 날리므로 NVS여야 한다) ② **SY6970 최소
드라이버** — 워치독 해제, 입력 전류 한도 상향, VBUS/충전 텔레메트리.
지금 안정한 것은 배터리가 마진을 빌려준 상태이지 고쳐진 상태가 아니다.
