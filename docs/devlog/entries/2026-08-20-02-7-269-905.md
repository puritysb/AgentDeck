# 2026-08-20 — 적대적 리뷰가 잡은 7건, 그리고 269,905 바이트가 거짓말이었던 이유

### 문제

문서 2커밋(브랜드 마크 6개 세기)과 죽은 코드 삭제 1건을 머지하려던 자리다. 세 건 다
CI 초록이었고, 삭제 건은 시뮬레이터 6개 씬이 바이트 동일이라는 실측까지 붙어 있었다.
그 상태에서 적대적 리뷰 2종(correctness / 계약·회귀)을 돌렸더니 **7건**이 나왔고,
그중 2건은 리뷰어 없이는 머지된 뒤에도 발견되지 않았을 것들이다.

### 해결

**① 삭제한 코드 자리에 남긴 주석이 거짓이었다.** `office.cpp` 의 `agentShort` /
`stateColor` 를 "파일 생성 이래 호출부 없음"이라고 한 묶음으로 적었는데, `stateColor`
는 생성 커밋(#16)에 호출부가 **둘** 있었다 — `:569` 책상 상태 틴트와 `:555` 재그리기
서명 해시. 9일 뒤 `de6b1519 "Fix IPS10 HUD stack smash"` 가 둘 다 걷어냈다. 코드를
지우고 남긴 주석은 **그 자리의 유일한 기록**이 되므로, 틀리면 미래의 독자가 스택
스매시 수정이 지운 경로를 "원래 없던 기능"으로 오해하고 되살린다. 두 함수의 서로 다른
이력으로 다시 쓰고, 죽은 사본의 idle 값이 이미 라이브와 어긋나 있었다는 것(`0x7a8a9c`
vs 인라인 `0x9fb0ac`)도 함께 남겼다 — 사본이 화면과 불일치해도 아무도 모른다는 증거다.

**② 펌웨어 바이너리 델타를 처음 잰 값 269,905 는 코드와 무관했다.** `ips10` 을
before/after 로 빌드해 비교했더니 26만 바이트가 달랐다. 죽은 코드 28줄로는 설명이
안 되는 크기다. 원인은 계측기였다 — after 쪽 워킹트리가 dirty 라 `git_rev.py` 가
`GIT_SHA` 에 `-dirty` 여섯 글자를 붙였고, 그 문자열이 .rodata 를 통째로 밀었다.
**동일 소스 재빌드로 잡음 하한을 먼저 재고**(75 바이트, `BUILD_EPOCH`), dirty 플래그를
양쪽에 고정한 뒤 다시 재니 **72 바이트** — 잡음보다 낮다. 죽은 코드는 애초에 방출된
적이 없었다.

**③ 산문 속 숫자에는 게이트가 없고, 그래서 스윕이 곧 게이트다.** 토큰 미러 개수를
6→7 로 고치는 패스를 두 번 돌렸는데 두 번 다 한 파일씩 놓쳤다. 1차는 `DESIGN.md`
(published spec — CLAUDE.md 와 정면 충돌한 채 남았고, 게다가 "검증기가 정확히 그
미러 집합을 게이트한다"는 거짓 단언까지 달고 있었다). 2차는 `viewer/app.js` 3개
로케일의 "5개 에이전트 마크"(디렉터리를 열거해 6개를 그려놓고 캡션만 다섯). 놓친
이유가 둘 다 스윕 자체에 있다 — `.md/.html/.json` 만 뒤지고 `.js` 를 뺐고,
`"six mirrors"` 로 찾았는데 문서는 `"all six mirrors"` 였다.

### 핵심 설계 결정

- **SSOT 로 접는 것이 항상 정답은 아니다.** 손복제본을 발견하면 SSOT 호출로 바꾸는
  것이 반사적 대응이지만, 그 함수에 호출부가 없다면 접어봐야 **아무도 안 부르는 심볼**
  이 남을 뿐이고, 접는 과정에서 행동 변경(정확일치 전환 → unknown 폴백이 `"Agent"`
  에서 raw id 로)까지 딸려온다. 사본을 만나면 **렌더러가 그걸 읽는지부터** 확인한다.
- **바이너리 델타 비교는 두 팔의 git 상태를 고정하고, 잡음 하한을 먼저 잰다.**
  `GIT_SHA`/`BUILD_EPOCH` 주입이 있는 트리에서 "before/after 해시가 다르다"는 그
  자체로 아무 정보가 아니다. 무변경 재빌드 델타가 기준선이다.
- **PR 게이트 중 C++ 를 컴파일하는 것이 없다.** `ci.yml` 은 vitest 계열뿐이고
  `design/lint.sh` 의 스코프는 `.html/.css/.js/.jsx` 다. 시뮬레이터를 실제로 굽는
  잡(`test-report.yml` → `pnpm demo:build`, env `ips10`)은 `on: push: branches:[master]`
  라 **머지 후에만** 돈다. 즉 ESP32 변경의 PR 초록은 변경 파일을 본 적이 없는 초록이고,
  로컬 `render.sh` + 바이너리 델타가 유일한 증거다. 죽은 맵 두 개가 두 달간 Kiro 수정을
  받아낸 것도 같은 공백에서 나왔다.
- **인용에는 앵커를 달아 게이트 안으로 넣는다.** `docs:check` 는 `#anchor` 가 없으면
  파일 경로만 검증한다. `DESIGN.md` 의 `design/RESOURCES.md § Third-party brand
  provenance` 인용에 앵커를 붙여 섹션 이름까지 검증되게 했고, 없는 앵커를 가리키게
  하는 뮤테이션으로 게이트가 진짜 실패하는지 확인했다.
- **`office.cpp` 의 unknown 폴백은 규칙 위반이 아니다(정정).** `agentColor` /
  `agentGlyphA8` 은 중립 폴백을 가진 allow-list 라 미지 에이전트는 마크 없이 중립
  회색으로 그려진다. 남는 문제는 그 중립 회색 `0x9aa0a8` 이 `opencode` 행과 **같은
  값**이라 화면에서 구분되지 않는 가독성 충돌이라는 것, 그리고 OpenClaw `0xFF6B5B` /
  Antigravity `0xD2D6DC` 가 `--brand-*` 토큰(`#FF4D4D` / `#5F6368`)이 아니라는 것.
  둘 다 렌더 델타가 생기므로 별건으로 남긴다.
