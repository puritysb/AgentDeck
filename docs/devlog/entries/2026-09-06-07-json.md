# 2026-09-06 — 판정 요청이 JSON을 "바라는" 대신 요구한다

`callMlx`/`callOpenAICompatible`는 프롬프트로 strict JSON을 요구하고 응답을 JSON으로
파싱하면서, 정작 서버에는 `response_format`을 보내지 않았다. 모델이 객체를 산문으로
감싸면 판정 불가 → 재시도 → 30분 park 가 반복된다. 실측: 이 기기의 데몬 로그에서 task
`de9afcc5` 한 건이 오늘 3시간에 6회(02:00·02:28·02:34·03:02·03:39·04:38) park 됐고,
같은 로그의 park 는 9/3 이후 17회다. park 는 만료되면 다시 시도되므로 루프가 끊기지 않고
그 task 는 끝내 판정되지 않는다.

이제 두 레그 모두 `response_format: {"type":"json_object"}`를 보낸다. 다만 이 필드는
보편적이지 않다 — `apme.judge.endpoint`는 임의의 OpenAI 호환 서버일 수 있고 일부는
400/422로 거부한다. 그런 서버가 판정을 통째로 잃으면 안 되므로 **거부 시 필드 없이 1회
재시도**하고 그 엔드포인트를 기억한다(탐색 비용 = 프로세스당 엔드포인트 1회). 401·429·
5xx는 필드 거부가 아니라 요청·계정 문제이므로 그대로 올린다 — 재시도하면 인증 실패가
동일한 두 번째 실패 뒤에 숨는다. MLX의 context overflow 400은 같은 400이지만 기존 압축
재시도 경로를 그대로 타며 JSON 모드를 유지한다(이 구분을 없애면 오버플로 테스트가 깨진다).

검증: 새 테스트 6개, 뮤테이션 5회 전부 빨강(두 레그의 필드 제거, 401을 필드 거부로 취급,
거부 기억 제거, 오버플로보다 필드 거부를 먼저 판정). 전체 Vitest 260파일 4,064 통과·1 skip.
로컬 MLX(gemma-4-26b, :8800)로 실제 판정 1회 왕복 6.7초, 반환값이 그대로 `JSON.parse`
됐다. 남은 판정 관련 항목은 #286에 있다.
