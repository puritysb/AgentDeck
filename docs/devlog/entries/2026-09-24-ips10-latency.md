# 2026-09-24 — IPS10 upload pacing and UI rendering latency

The preceding device investigation separated voice capture, upload, host transcription, personal-agent execution and speech staging. One 843,072-byte upload took 36.382 seconds: the network loop slept 20 ms after every 512-byte successful write. A separate request spent 107.335 seconds between personal-agent acceptance and final reply; that host-side wait is not IPS10 CPU time. The earlier workspace update timing excluded LVGL drawing/flush and was not evidence of touch responsiveness.

Voice uploads now send bounded 2 KiB bursts, yielding one scheduler tick between bursts and backing off on socket pressure. The 60 KiB internal-memory reserve is checked throughout transmission; deadlines and control-channel draining remain. Logs report elapsed upload time, minimum observed internal free memory and pressure waits. Three initial device requests uploaded 968,512 / 198,976 / 704,832 bytes in 4.163 / 0.288 / 0.828 seconds respectively, all HTTP 200 on the first attempt, followed by personal-agent speech playback without reboot. These are different recording lengths, not a controlled identical-payload benchmark.

Repeated assignment of unchanged creature/brand image sources no longer invalidates them. Rolling UI diagnostics now separate widget work, LVGL work, touch read duration and touch poll gaps; loop count is explicitly not panel FPS. Even after source-assignment gating, the first device run found median five-second maxima of 234.4 ms for LVGL work and 267.6 ms for input poll gaps (excluding initial startup samples), while touch reads were typically a few milliseconds. This establishes rendering stalls independently of the touch controller.

The static ocean is now scaled and blended once at initialization using LVGL itself, then reused as an opaque image source. Its single bounded 2,048,000-byte device-lifetime cache lives in PSRAM and is reused across screen rebuilds; the hot draw/PPA buffers remain in internal SRAM. Allocation failure retains the original flash-image rendering path. The renderer supports both 1280×800 and 800×1280. Native comparison with the previous reference shows average absolute channel differences below 0.007/255, confined to minor transformed-edge rasterization differences.

The voice strip distinguishes Sending audio, Recognizing speech and Processing. The device no longer reopens wake detection after 25 seconds while a personal turn is still pending. It shows a delayed-processing notice and retains the pending phase, with an eleven-minute recovery bound beyond the host's ten-minute turn timeout. No model, personal session or agent configuration was changed.

Validation: firmware build; native landscape and portrait interaction/USAGE/voice-state suites; JavaScript build/typecheck and 4,665 tests passed, two skipped; protocol generation has no drift and token mirrors pass. Design lint retains 171 pre-existing source/build-output findings. First deployment's resume HTTP response timed out after the request was processed; a bounded retry confirmed `wasSuspended: false`.

Final cache deployment: firmware SHA256 `50b8ae3ba6d123afcb74dc7b618035e08ded0281d4cfb47353dcc9d9abbaddbd`, build epoch `1790181638`. Over the 200-second observation, the median five-second maximum LVGL time fell from 234.4 to 144.3 ms and touch poll gap from 267.6 to 172.4 ms (startup excluded). The worst observed post-startup gap fell from 710.0 to 443.1 ms. These are successive live-workload observations, not identical-scene or physical finger-to-photon measurements. Large content changes still cause noticeable stalls; this is an improvement, not proof of universally smooth touch response.

Two final-build acoustic turns uploaded 730,432 and 691,520 bytes in 0.851 and 0.751 seconds, both first-attempt HTTP 200 with spoken replies. A third playback of the synthetic wake phrase was not detected, so this does not establish wake-word or recognition accuracy. The device stayed up for the full observation, retained live USAGE and five sessions/four projects, and returned to wake state. Internal free memory settled around 105–108 KiB, largest block around 62–65 KiB, minimum free 58 KiB. The final deployment's serial lease resumed successfully. Capture endpointing still sometimes waits over twenty seconds in this acoustic setup; the fixed RMS detector and server execution time remain separate limitations.

A firmware-level pending-state regression injected a delivered result without a final response and confirmed `waiting` beyond thirty seconds. An empty playback begin/end restored the idle phase. The subsequent immediate synthetic wake replay was also missed; no additional successful voice turn is claimed. This diagnostic used the existing serial protocol and did not send a command to the personal agent. Device reboot/readback clears the synthetic diagnostic transcript before returning the unit to normal operation.
