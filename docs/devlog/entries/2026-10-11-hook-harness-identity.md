# 2026-10-11 — A Codex turn reaching a Claude hook endpoint became a Claude Code session (#490)

During the App Store 1.8.0 (7801) audit on 2026-10-09, one completed answer appeared twice at 12:43, once under the Claude Code icon and once under Codex. The roster labelled the session Claude Code while reporting an OpenAI model. The work was a single Codex thread (`codex-cli`, `gpt-6-astra`, turn 12:40:50–12:47:09 in `apme.sqlite`). No `claude-code` APME run existed in that window, and the persisted timelines no longer held the duplicate, so it lived in live session and timeline state.

**Mechanism.** Both daemons chose the harness from the endpoint name. `codex_*`, `opencode_*` and `hermes_*` carry it in the prefix, and every unprefixed name (`/hooks/Stop`, the Swift `/hook` body's `event`) was treated as Claude Code. Codex uses Claude's lifecycle vocabulary (`hook_event_name: "Stop"`, `session_id`, `transcript_path`, `last_assistant_message`, captured verbatim from codex-cli 0.160.1). It also runs every command configured for an event, and codex-cli 0.160 ships an external-agent import (`/import`, "import setup … from Claude Code") whose strings name Claude's `settings.json` hook events and a `hooks.json` target. A Claude-shaped AgentDeck command running under Codex therefore delivers a Codex event to an unprefixed endpoint. The Swift daemon then resurrected a `claude-code` row keyed by the bare thread id (the Codex row is `codex:<id>`), and `ObservedAgentSettings.claude(fromHook:)` stamped the payload's `gpt-*` model on it. The Node daemon labelled the turn's `chat_start`/`chat_response` `claude-code`. Because the thread id was also the Codex run's key, no Claude APME run was opened, which matches the database. A daemon e2e test replaying the captured payloads over HTTP reproduces it: on the base build the Codex turn's rows came back `claude-code`.

A second defect surfaced in the same replay. Timeline exact dedup (`deduplicateEntry` step 2, and the Swift `DaemonTimelineStore.add`) compared type + text only, except for `scheduled` rows. A second real Codex thread answering `pong` within 8 s lost its reply.

**Fix.** `shared/src/hook-harness.ts` decides the harness from the payload. It is a generated SSOT (`pnpm generate-hook-harness` → `CodexHookHarness.generated.swift`) with vectors in `shared/hook-harness-vectors.json` that both suites replay. Codex-only evidence (a Codex thread key, notify's `agent-turn-complete`, or a rollout `transcript_path`) routes an unprefixed hook to its `codex_*` event. A Codex payload with no Codex route is dropped. The model and provider are never evidence (`claude-glm` stays Claude). One Codex event instance (event + thread + turn/tool/start source) is ingested once within 10 s, and a payload without that discriminator is never deduplicated. Swift skips Claude steering for a Codex payload on `/hooks/PreToolUse` or `/hooks/Stop` and answers it with an empty body, so a queued deck directive is never handed to Codex. Node fills `session_id` from notify's `thread-id`, where it previously fell into the anonymous `daemon-hook` bucket. Timeline exact dedup is now per session for every row type, comparing the bare id form.

**What is not proven.** The 12:43 capture is gone, so this does not show which command delivered the generic copy on the audit machine. On that machine the user-global `~/.codex/config.toml` held only AgentDeck's `codex_*` hooks and workmux's, there is no `~/.codex/hooks.json` today, and Codex's `notify` pointed at Computer Use, so the delivering command may have been a since-removed import, a project-level hook, or a path not yet identified. What is proven is that the identity hazard reproduces with real Codex payloads, and that both daemons now converge a Codex payload on the Codex identity from whichever endpoint it arrives at.
