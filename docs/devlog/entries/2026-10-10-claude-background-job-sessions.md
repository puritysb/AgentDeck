# 2026-10-10 — Claude background jobs: the working session was invisible, a spare and a parked window showed instead

The owner was working in a Claude Code session on OpenClaw, and AgentDeck showed only idle OpenClaw rows. The session had been moved to the background: Claude Code 2.1.296 forked the conversation into a background job (`5b55b9d6`, `kind: "bg"`, launched as `~/.local/share/claude/versions/2.1.296 --session-id 5b55b9d6… --fork-session --resume …/d385adf6….jsonl` under a `--bg-pty-host`) and left the original window (`d385adf6`) alive with `parkedJobId: "5b55b9d6"`, emitting no more hooks. Beside them stood a pre-warmed spare (`64cf355f`, `spare: true`, `claude bg-spare --bg-spare …`).

**Why each row was wrong.** The Node observer admits a process only when argv[0] is named `claude`; the job's argv[0] is named after its version, so the conversation the owner was typing into had no row. Hooks only overlay observer rows, so its live `PreToolUse`/`Stop` hooks were discarded. The parked window kept its row (idle), and the spare, whose argv does say `claude` and which has a session file, became a second idle OpenClaw row. The spare also fires a startup `SessionStart`, which opened an APME run (no prompt, `abandoned` 30 min later); the Swift daemon, which builds Claude rows from hooks, would have minted an idle row for it.

**Fix.** The Node observer admits the versioned binary (argv[0] only) and never the PTY host, and reads `kind`/`jobId`/`parkedJobId`/`spare` from the session file: spares are dropped, and a window yields to its job only while that job is alive in the same scan. Both hook paths classify the hook's process by argv with a new generated rule (`shared/src/claude-background-jobs.ts` → Swift): a spare's startup `SessionStart` is dropped; a job forked from `<OLD>` closes `<OLD>`'s APME run, and the Swift daemon, which cannot read the session file, also retires `<OLD>`'s idle row. The deck now shows one OpenClaw row for the conversation, where it showed two idle rows and missed the working one.

**Background work vs. a background job.** Background work inside a session already renders without adding rows: subagents and folded `codex exec` children as the census (Terrarium ring and satellites, `+N`), Claude `background_tasks` as orbits, coordination as "waiting on". A Claude background job is different, because it *is* the user's conversation and nothing on disk names a parent to fold it under, so it stays a row (replacing the window it came from).

**Other agents, same audit.** OpenCode's Task tool ran each child as its own session row in both daemons. The observer plugin (v3) now reports a child (`parentID`) as `opencode_subagent_start`/`stop` into the parent's census, and surfaces a child's permission request on the parent's row while still resolving it against the child. Open, not fixed here: the OpenClaw adapter follows whichever session key spoke last (a cron or subagent run can take the row and receive a device prompt), a Codex rollout open in two processes keeps the first process's pid/type, and two Antigravity processes in one cwd can emit the same id.
