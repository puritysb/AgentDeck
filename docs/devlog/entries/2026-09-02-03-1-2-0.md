# 2026-09-02 — 1.2.0 여섯 채널 컷: 태그를 한 번에 밀면 아무 일도 일어나지 않는다

### 문제

여섯 채널을 한 라운드로 컷하면서, 저장소가 기록해 둔 외부 상태가 두 곳에서
실제와 달랐고 도구의 상태 보고를 두 번 오독했다.

### 해결

npm 1.2.0은 레지스트리에서 4패키지 모두 확인됐고, Apple 양 플랫폼(빌드
5801)·Stream Deck 1.2·Ulanzi 1.2.0·Play(versionCode 15)가 심사에 올라갔으며
Android/ESP32 GitHub 릴리스가 게시됐다(ESP32는 12보드 62에셋).

- **태그 6개를 한 push로 밀면 워크플로가 하나도 발화하지 않는다.** GitHub는
  3개를 넘는 태그를 담은 push에 이벤트를 만들지 않는다. 여섯 태그가 원격에
  올라갔는데 릴리스 워크플로의 최신 런은 지난달 것이었고, 아무것도 빨갛지
  않았다. 원격 태그를 지우고 개별 push로 복구했다(RELEASING.md에 규칙화).
- **Ulanzi 포털의 심사 대기 레코드는 1.0.4가 아니라 이미 1.0.5로 교체돼
  있었다** — 업데이트 노트가 증거였다. 저장소 기록이 한 버전 낡아 있었고,
  CHANGELOG·README·LISTING·GH 릴리스 본문을 실측대로 되돌렸다. 갱신 경로도
  철회+재생성이 아니라 **Edit review work**(in-place)가 맞았다. ZIP 재파싱은
  7개 언어 카피를 한 줄로 리셋하고 Dial을 재선택하므로 정본에서 복원해야 한다.
- **ASC는 ko/ja "새로운 기능"이 비면 "심사에 추가"를 무언 실패시킨다.**
  버튼이 눌린 것처럼 보이고 제출 이력에는 아무것도 생기지 않는다.

### 핵심 설계 결정

**런 레벨 상태는 잡보다 늦고, 취소는 되돌릴 수 없다.** ESP32 릴리스 런이
55분간 `queued`로 보여 8/26 장애의 재발로 판단하고 취소했는데, 잡 목록을
보니 12보드 매트릭스가 실제로 빌드 중이었고 9개는 이미 성공한 상태였다.
2개 잡이 잘렸고 `rerun --failed`로 복구했다. 파괴적 명령 앞에서는 런 상태가
아니라 **잡 목록**을 근거로 삼아야 한다 — "queued"는 좀비의 증거가 아니다.
