# 2026-08-06 — 로컬 추론 지도를 그리다 나온 다섯 건: 문서가 코드보다 오래 살아남는 방식

### 문제

"우리가 로컬 모델을 어떻게 쓰고 있는지 도식화하라" 에서 출발했다. 코드를 훑어 지도를 그리는
동안, **문서와 설정 파일이 코드와 갈라진 지점**들이 연달아 나왔다. 공통점은 하나다 —
*소비자가 없는 선언은 틀려도 아무도 모른다.*

1. **같은 요약, 다른 모델**: Swift `TimelineSummarizer` 는 FoundationModels → MLX → Ollama →
   휴리스틱인데, Node `timeline-summarizer.ts` 에는 FM 단계가 없었다(MLX부터 시작).
   같은 맥에서 어느 데몬이 떠 있느냐로 요약 품질이 갈렸고, MLX 를 안 띄운 CLI 사용자는
   Apple Intelligence 가 멀쩡해도 휴리스틱 행을 봤다. 같은 프로세스의 `session-activity.ts`
   는 이미 FM 을 부르고 있었으니, 한 데몬 안에 두 정책이 공존한 셈.
2. **임베딩 전용 모델이 judge 후보로**: `detectLocalJudgeProviders()` 가 Ollama `/api/tags`
   의 이름만 읽어 `bge-m3` 같은 임베더를 후보로 띄웠다. 고른 뒤 첫 판정 호출에서야 실패한다.
3. **`config/default-settings.json` 을 읽는 코드가 없다**: 문서는 "첫 실행 때 복사된다"고
   했지만 복사·독해 코드가 없었다. 7개 최상위 키 중 6개는 어떤 로더도 읽지 않았고
   (`bridgePort` 는 CLI/데몬 할당자, 타임아웃들은 컴파일 상수), 값도 코드와 어긋나 있었다
   (`judge.backend` 파일=mlx vs 코드=foundationModels). `whisperModel` 은 whisper.cpp
   제거 후 남은 화석.
4. **pricing 술어가 자기 태그를 못 알아봄**: `isLocalModel()` 이 `foundationmodels` 전체
   일치만 봐서, 이 저장소가 스스로 만드는 `foundationModels:apple-intelligence`(judge 태그)와
   MLX 서버가 광고하는 `mlx-community/…` 가 UNKNOWN_PRICE 로 떨어졌다 — `isPricedModel()`
   소비자에게는 "$0" 이 아니라 "가격 미상" 으로 읽힌다.
5. **이름만 웨이크워드였던 펌웨어**: `esp32/src/audio/wake_word.cpp` 는 I2S PDM 캡처 +
   RMS VAD 까지만이고 텐서 인터프리터를 부르지 않았다. 어떤 보드도 `Audio::wakeWordInit` 을
   호출하지 않았고, 유일한 게이트 `BOARD_HAS_AUDIO` 는 코덱 달린 보드에서 `0`, 나머지는 주석.
   63,520 B 모델은 397 KB C 배열 헤더로 매 빌드를 따라다녔다.

추가로 `docs/apme.md` 는 `tuner.ts` / `ApmeTuner.tune()` / `shouldRetune()` /
`POST /apme/tune` 을 동작하는 기능으로 서술하고 있었다. **넷 다 저장소에 없다.**

### 해결

- Node 요약 체인 앞에 FM 단계를 붙여 Swift `.auto` 와 순서를 일치시켰다. 프로브는 최초 1회만
  (그 뒤엔 생성 호출 자체가 생존 확인), 실패는 기존 60초 재시도 사다리를 탄다.
- judge 자동탐지는 Ollama 가 주는 `capabilities` 로 `completion` 가능 모델만 통과시킨다.
  TS + Swift 미러 동시 수정.
- `default-settings.json` 을 읽히는 키만 남기고 코드 기본값과 일치시킨 뒤
  **드리프트 게이트**(`bridge/src/__tests__/default-settings-drift.test.ts`)를 붙였다.
  `docs/configuration.md` 는 실제 설정 표면으로 재작성.
- `isLocalModel()` 을 접두어 매칭으로 바꾸고(`foundationmodels:`, `mlx-community/`,
  `lmstudio:` …), `normalizeModelId()` 가 로컬 id 의 org 세그먼트를 자르지 않게 했다.
- ESP32 웨이크워드 코드 3파일 + `BOARD_HAS_AUDIO` + 빌드 제외 규칙 삭제. 훈련 산출물
  `esp32/models/openclaw_wake_word.tflite` 는 보존하고, `docs/wake-word.md` 에 제거 이유 ·
  재개 조건 3가지 · 복원 지점을 적었다.
- `docs/apme.md` 의 auto-tuning 절은 "설계만 있고 미구현" 으로 명시하고, HTTP 라우트 표를
  `http.ts` 실제 분기와 1:1로 맞췄다(유령 `POST /apme/tune` 삭제, `tasks/:id` · `samples` ·
  `pareto` · `judge/detect` 추가).

### 핵심 설계 결정

- **부재는 정보 없음이지 불가가 아니다.** Ollama `capabilities` 필드가 *없는* 항목은 남긴다 —
  구버전 Ollama 가 필드를 안 주기 때문. 대신 `/api/tags` 가 답한 뒤에는 `/v1/models` 로
  폴백하지 않는다: 호환 shim 은 능력 정보를 안 주므로 방금 거른 모델이 되살아난다.
  (`usageStale` 에서 배운 것과 같은 축: 신호의 부재를 하드 신호로 접지 말 것.)
- **소비자 없는 선언에는 게이트를 붙이거나, 선언을 지운다.** `default-settings.json` 은 읽는
  코드가 없으므로 값이 틀려도 아무것도 깨지지 않았다. 파일을 남기기로 한 이상 테스트가
  소비자 역할을 한다 — 값 불일치도, 안 읽는 키 추가도 빌드를 깬다.
- **문서가 설계 스케치일 때는 그렇게 쓴다.** apme.md 의 튜너 절은 지우지 않고 라벨을 붙였다.
  저장 구조(`rubrics` 버전 관리, `vibe_feedback`)는 실제로 있으므로, 재개할 사람에게는
  설계가 자산이다. 다만 "있는 기능" 처럼 읽히면 그때부터는 부채다.
- **"미배선" 은 존재 주장보다 검증 비용이 크다.** pricing 을 처음에 "배선 전" 이라고 잘못
  보고했다 — `priceFor` 만 grep 했고 실제 소비자는 `priceUsd()` / `providerFor()`
  (`apme/collector.ts`) 였다. 모듈이 죽었다고 말하기 전에 export 표면 전체를 grep 할 것.
- **펌웨어는 이름이 아니라 동작으로 판단한다.** 웨이크워드 파일은 5개월 동안 "준비된 코드"로
  문서에 실려 있었지만 추론을 한 적이 없다. 지우고 재개 조건 3가지(상시 켤 마이크,
  실제 TFLite Micro 경로, 실기 검증)를 명시하는 편이 다음 사람에게 정직하다.

검증: vitest 2,581 통과(신규 20건) · macOS `BUILD SUCCEEDED` · ESP32 `ips10`/`amoled`/
`t_embed` 컴파일 · `docs:check` · `design-system:check`.

### 후속 — 같은 지도를 재검증하다 나온 whisper 잔재

지도를 실제 프로세스/설정으로 다시 대조하면서 걸린 나머지. **엔진은 2026-07-26 에 갈아탔는데
그 엔진을 부르던 배선의 이름·로그·문서가 그대로 남아 있었다.**

- `check-deps.ts` 가 `whisper-cli` / `whisper-server` 를 선택 의존성으로 프로브하며
  `brew install whisper-cpp && whisper-cli --download-model large-v3-turbo` 를 안내했다.
  **부르는 코드가 없는 바이너리를 사용자에게 설치시키는 안내**가 남아 있던 셈. 삭제.
- `VoiceManager.connectToServer()` / `disconnectFromServer()` — 전자는 실제로는 헬퍼 프로브,
  후자는 완전한 no-op 이었다. `probeSpeechHelper()` 로 개명하고 no-op 은 호출부(index.ts ·
  daemon-server.ts teardown 2곳)와 함께 삭제. 실패 로그도
  `whisper-server connection failed` → `speech helper probe failed` 로 정정 —
  **원인이 엉뚱하게 찍히는 로그는 없느니만 못하다.**
- `docs/daemon.md` 의 `## Whisper-server` 절이 포트 **9100** 과
  `~/.agentdeck/whisper-server.json` 을 살아 있는 계약처럼 서술하고 있었다(둘 다 없음). 삭제.
  `docs/protocol.md` 파일 트리의 `whisper-server-manager.ts` 줄, 아키텍처 ASCII 도식의
  `whisper.cpp` 상자, `architecture/devices/android-ui/testing` 의 "whisper transcription"
  서술도 함께 정정.

남긴 것: "왜 뺐나" 를 적은 코드 주석, `docs/voice-setup.md § Why we removed whisper.cpp`,
`retired-surfaces.md`, App Store 문서의 **금지 문자열 목록**(`whisper-cli` 가 *없어야 한다*는
검증용이라 정확). 판별 기준은 하나 — **그 문장이 지금의 동작을 주장하는가, 과거를 기록하는가.**

같은 재검증에서 지도 자체의 오류도 나왔다: 판정 lane 은 이 기기에서 FM→MLX 가 아니라
`backend:"mlx"` 고정으로 **MLX 직행**(FM 미진입), `session-activity` 는 폴백이 아니라
**휴리스틱 먼저 → FM 이 나중에 덮어쓰기**, `POST /generate` 는 "콜드 7초 회피" 가 아니라
**왕복 4–22 s 실측**, TTS 는 한 갈래가 아니라 **둘**(기기 응답 = fm-helper `speak`,
웨이크워드 대화 = macOS `say`). 도식은 코드보다 빨리 낡는다.

검증: vitest 2,609 통과 · `pnpm build` 전체 · `docs:check` 91파일.
