# 2026-08-19 — 릴리즈 노트를 안 쓴 게 아니라, 쓴 걸 아무도 읽히지 않게 발행하고 있었다

### 문제

"GitHub 에 릴리즈 노트를 올리고 있으니 잘 남고 있는 것 아니냐"는 점검 요청에서
시작했다. 태그는 실제로 6채널 전부 빠짐없이 나가고 있었다 — 문제는 **거기에
담긴 내용**이었다.

릴리즈 워크플로 6개가 전부 `body:` 를 하드코딩하고 있었다. `npm-v1.0.21` 의
릴리즈 본문은 전체 18줄, 제목 · 한 줄 설명 · `npx @agentdeck/setup` · 패키지
표가 전부다. 1.0.20→1.0.21 사이에 무엇이 바뀌었는지 한 글자도 없고 CHANGELOG
링크조차 없다. 나머지 5채널도 같은 모양이라, **매 버전 동일한 설치 안내가
"릴리즈 노트"라는 이름으로 올라가고 있었다.**

변경 내역은 CHANGELOG.md 에 쓰고 있었지만 마지막 갱신이 `1d92d462`(Android
1.0.9)에서 멈춰 있었다. 그 이후 45 커밋, 그리고 2026-08-18 에 5채널이 커트됐는데
항목이 하나도 없다. 릴리즈 커밋 `dfabcc71` 이 건드린 파일은 버전 문자열과
RELEASING.md 뿐이다.

그 결과 이 라운드에 실려 나간 것들이 사용자가 읽을 수 있는 어디에도 없었다 —
**Kiro 관측 전체(~10 PR)**, 서브에이전트 인구조사, off-harness provider,
엔터프라이즈 network posture, 페어링 코드, 데몬 preferred port, Dock 아이콘
자동 숨김. README 의 `### Agents` 표는 Claude/Codex/OpenCode/OpenClaw 4행
그대로였고, `docs/` 에서 Kiro 를 언급하는 파일은 `cli.md` 와
`appstore-feature-matrix.md` 둘뿐이었다.

`RELEASING.md` 에는 "4. Update user-facing release notes and the delivery table
in README.md" 가 이미 있었다. 절차가 없어서가 아니라 **절차의 CHANGELOG 절반이
강제되지 않아서** 조용히 빠진 것이다. README 배포 표는 매 라운드 갱신되고
있었다 — 강제하는 게이트가 없어도 사람이 챙기는 쪽만 살아남았다.

### 해결

CHANGELOG 를 릴리즈 본문의 **유일한 출처**로 만들었다. `scripts/release-notes.mjs`
가 배송 태그를 CHANGELOG 섹션으로 해석해 본문을 렌더하고, 채널별 설치 안내는
`.github/release-notes/<channel>.md` 로 분리했다. 6개 워크플로 전부
`body:` → `body_path: notes.md`.

배선 중 두 개가 걸렸다. `apple` 과 `esp32` 의 `release` 잡에는 `actions/checkout`
이 **없었다** — 다른 잡이 만든 아티팩트만 퍼블리시하는 잡이라 스크립트도
CHANGELOG 도 없는 컨텍스트였다. ESP32 의 보드 표는 실제로 빌드된 아티팩트에서
렌더되므로 체크인된 템플릿이 될 수 없어 `--template` 으로 넘긴다.

CHANGELOG 는 헤딩을 `## <날짜> — <채널> <버전>` 으로 전환하고 2026-08-18 라운드를
백필했다. 다섯 태그가 전부 같은 커밋(`dfabcc71`)을 가리키므로 이 라운드는 공유
라운드가 맞고, 헤딩 하나가 다섯 채널을 모두 이름한다.

재발 방지는 `verify-release-version.mjs` 에 넣었다. 이 스텝은 모든 릴리즈
워크플로의 **첫 스텝**이라 빌드 · 퍼블리시 · 태그 어느 것보다 앞선다.

### 핵심 설계 결정

**노트를 안 쓴 것과, 쓴 노트가 발행되지 않는 것은 다른 실패다.** 그리고 후자가
더 오래 산다 — 전자는 빈 릴리즈 페이지로 보이지만, 후자는 매번 그럴듯한 본문이
올라가므로 아무도 이상하게 여기지 않는다. 다섯 채널이 새 관측 에이전트를 통째로
싣고 나가는 동안 릴리즈 페이지 다섯 장이 전부 "설치법"만 보여주고 있었고,
CI 는 내내 green 이었다.

**채널이 패치 번호를 공유하지 않게 된 순간 bare 버전 헤딩은 오답을 낸다.**
`## 1.0.7` 은 2026-08-06 의 npm 이었고 Apple 은 2026-08-18 에 1.0.7 에 도달했다 —
내용이 완전히 다르다. 그래서 매처에 **bare 폴백을 두지 않았다**. 한 채널의
노트를 다른 채널의 태그로 발행하는 것은 노트를 안 내는 것보다 나쁘다. 접두
오매치(`1.0.2` ↔ `1.0.21`)도 같은 이유로 테스트가 고정한다.

**사후 재구성은 하지 않았다.** 노트 없이 나간 나머지(npm 1.0.9–1.0.18, apple
1.0.4–1.0.6, android 1.0.5–1.0.8, streamdeck 1.0.4–1.0.5, esp32 1.0.2–1.0.4)는
"Known gaps" 로 명시만 하고 비워뒀다. 커밋 로그에서 그럴듯한 문장을 지어내면
아무도 측정하지 않은 것을 릴리즈 노트로 발행하는 셈이고, 그건 없는 것보다
나쁘다. 유일한 예외가 Ulanzi 1.0.3 — 심사 중이라 재커트 가능성이 있어서
`plugin-ulanzi/` 를 실제로 건드린 커밋만 골라 백필했다.

**게이트는 링크를 검사하지 신선도를 검사하지 않는다.** `docs:check` 와
`design-system:check` 는 이 사건 내내 green 이었다 — 링크 · 커버리지 · H1 만
보기 때문에, Kiro 가 어느 문서에도 없어도 통과한다. 문서 신선도를 강제하려면
그걸 강제하는 별도 게이트가 있어야 하고, 이번에는 릴리즈 경로에만 걸었다.
