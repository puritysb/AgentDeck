# 2026-11-02 — 2.0 integration boundaries

The owner requested collection on master, combined testing and then new product
recordings, with no release upload or version bump. Upstream Pages/habitat PRs
#640 and #642 were complete, while local controller/CloudKit changes had not
reached the same ancestry. Integration uses an isolated worktree rather than
resetting either side. The explicit Dot native/local experiment remains separate.

The Codex reviewer branch had already been incorporated behaviorally: resolving
its conflicts to the newer tests retained Blender-specific evidence, OpenCode
process-exit cleanup and the CloudKit source entries. Only older receipts were
new. The completed Swift capability branch adds independent native/recovery work.

Two OpenCode contracts must survive together: CLI-installed plugins have an
active SDK response poller; native folder-installed observers deliberately do
not. A structured question from the latter must remain read-only even if its SDK
supports replies. Both question and permission capabilities honor observer-only
provenance. Pending Swift permission capability belongs to the individual wait,
not whichever hook happened to update its projection last. Explicit input denial
also survives compact serialization, the Node/Swift relay allow-list and D200H previews. The mixed-runtime relay vector compiles the actual native sanitizer and preserves the explicit false value. OpenCode input controls
require a recent command poll, and the unused Mac Command-Return `go on`
shortcut is removed alongside the generic buttons.

The host Homebrew Rust compiler had only the ARM target. Universal native Glance
builds failed with E0463 for the missing Intel standard library; standalone
version-matching standard libraries also refused the Homebrew compiler identity.
A private rustup installation pinned to CI's 1.90.0 with both Mac targets avoids
changing the user's global compiler. Reruns use explicit CARGO/RUSTUP_HOME and
CARGO_HOME paths; ARM-only success is not universal-build evidence.

The first combined quick check exposed a callback-scope regression: the bounded
plugin-disposal implementation moved `post` into the observer instance, but the
question reply/reconciliation helpers still referenced it from module scope.
Passing the instance callback through the existing steering loop restores both
transport-failure retry status and confirmed-gone request withdrawal. Existing
behavioral tests reproduced both failures; generated native observer and fixed
Pixoo resources also require regeneration from the combined source.

Pages and README now lead with agent activity, waiting and supported responses.
The 135-second habitat recording remains explicitly a development visualization,
not evidence that it demonstrates the complete controller workflow or ships in
the current Store release. Final 2.0 media must show the accepted response journey;
recording provenance and the collection gates live in [RELEASING.md](RELEASING.md#200-integration-target-2026-11-02).
