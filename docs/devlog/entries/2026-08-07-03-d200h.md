# 2026-08-07 — D200H 애니메이션은 하드웨어 한계가 아니었다: 구운 루프는 닫혀야 한다

### 문제

D200H 의 GIF 애니메이션은 `AGENTDECK_ULANZI_ANIM=1` 옵트인 뒤에 꺼져 있었고, 사유는
"기기가 못 따라간다" 로 기록돼 있었다. 재조사해 보니 한계가 아니었다. **Ulanzi Studio 는
GIF 를 기기에서 네이티브로 루프 재생**하므로 상태 전환당 1회만 푸시하면 되고 정상상태
애니메이션 비용이 0 이다 — 매 150ms 틱마다 다시 그려 보내는 Stream Deck 보다 이 축에서는
유리하다. 비싼 건 인코딩 쪽이었고, 실측하니 타일당 84ms / 71KB 중 **래스터가 83%**,
그런데 프레임 간 실제 픽셀 델타는 **7.9%** 였다. 즉 테두리만 움직이는데 타일 전체를 14번
다시 래스터하고 있었다.

조사 과정에서 애니메이션이 켜져 있어도 제대로 보이지 않았을 버그가 셋 더 나왔다. 셋 다
**라이브 티커에서는 발현이 불가능**해서 Stream Deck 에서는 아무도 볼 수 없었다.

### 해결

**인코딩**: 델타 프레임(직전 프레임과 같은 픽셀은 transparent index + disposal 1) +
루프 전체 단일 팔레트(64색) + 네이티브 144 래스터(`GIF_ICON_SIZE`) + 타일 SVG 키 캐시 +
프레임 단위로 이벤트 루프에 양보하는 **백그라운드 인코딩**(정적 PNG 즉시 푸시 → GIF 준비되면
업그레이드). processing 타일 71KB/84ms → 23.5KB, 프레임 14 → 24. 기본 ON (`=0` 옵트아웃).

**버그 ①  processing 대시는 D200H 에서 한 번도 움직인 적이 없다.**
`processingStartFrame` 을 넘기지 않으면 `startFrame = animFrame` 이 되어 위상이 회전을
정확히 자기상쇄한다(`offset = -(animFrame*speed - animFrame*speed) = 0`). SD 플러그인은
값을 넘겨서 정상이었다. 기본값을 `0` 으로.

**버그 ②  구운 루프가 닫히지 않았다.** orbit 속도 22/16 과 pulse 주파수 0.12/0.14 가
서로 비가환이라 wrap 마다 대시가 412px 점프했다. `ORBIT_SPEED_PX` 단일 속도와
`PULSE_OMEGA = π / SESSION_SLOT_ANIM_CYCLE` 로 모든 애니메이션 값이 한 주기(512/22)에
정확히 제자리로 돌아오게 했다.

**버그 ③  `svgFrame` 이 gradient id 를 `Math.random()` 으로 만들고 있었다.** 같은 타일의
두 렌더가 문자열로 달라진다. 소비자들이 그 문자열을 타일의 **신원**으로 쓰기 때문에 —
기기 푸시 dedup, "이 타일이 애니메이션하나" 판정, GIF 캐시 — 셋이 동시에 무력화됐다.
빈 키가 브로드캐스트마다 재전송되고, 빈 슬롯 4개가 애니메이션으로 오탐되어 매 렌더 재인코딩됐다.
색에서 파생시키자 오탐 6키 → 2키. 이웃한 cluster/grid frame id 는 원래부터 결정적이었고
이것만 예외였다.

**버튼별 위상**: 프레임들이 한 주기의 균등 샘플이므로 키마다 시작 인덱스를 바꾸는 것은
이미 렌더된 덱 배열의 **회전**이다 — 추가 렌더링 비용 0. 키 위치 기준 stride 7(프레임 수
24와 서로소)로 분산. 세션 id 가 아니라 위치를 쓴 이유는 타일 GIF 가 바이트 안정적이어야
캐시가 히트하기 때문.

### 핵심 설계 결정

- **구운 루프(GIF)는 닫혀야 하고, 라이브 티커는 그 사실을 숨긴다.** SD 는 `animFrame` 을
  무한 증가시키므로 주기가 서로 비가환이어도 아무 문제가 없다. 같은 렌더러를 구워서 쓰는
  순간 모든 애니메이션 값의 주기가 **공통 주기의 약수**여야 한다. 새 애니메이션 요소는
  반드시 `SESSION_SLOT_ANIM_CYCLE` 의 정수배 주기로 넣을 것. 게이트:
  `shared/src/__tests__/session-slot-anim.test.ts`, `plugin-ulanzi/src/__tests__/anim-schedule.test.ts`.
- **렌더 산출물이 신원으로 쓰이면 결정적이어야 한다.** 랜덤 id 는 화면상 완벽히 정상이면서
  dedup·변경감지·캐시를 한꺼번에 깨뜨린다. 렌더러에 `Math.random()` 금지.
- **회전은 한 곳에서만 정의한다.** 프레임 수집과 "이 타일 아직 유효한가" 검사가 회전을 각자
  유도하면 어긋난다 — 실제로 어긋나서 위상이 0 이 아닌 모든 키가 영원히 stale 로 판정돼
  인코딩이 무한 취소·재큐됐고, **증상은 그냥 "애니메이션이 안 됨"** 이었다. `frameOrderFor()`
  단일 정의로 통합. 이 회귀는 유닛 테스트가 아니라 **실기기 로그**가 잡았다.
- **파리티**: D200H 는 plugin-ulanzi 가 유일 드라이버이고 렌더링도 플러그인이 한다. 데몬
  (Node CLI / Swift 인프로세스)은 상태만 흘려보내므로 **두 데몬에서 동작이 동일**하다. Swift
  D200H 프리뷰는 의도적 정적 미러라 수정 불필요. 단 `apple/AgentDeck/Rendering/SessionSlotRenderer.swift`
  가 같은 TS 렌더러를 복제한 **Stream Deck 프리뷰용 미러**라 `PULSE_OMEGA` 를 포팅하고
  SYNC-HASH 핀을 범프했다(`check-preview-mirror-sync` 가 정확히 이걸 잡음). 링 속도와
  start-frame 은 그 미러가 애초에 안 그려서 포팅 대상이 아니었고, 그 사실을 파일에 기록해 뒀다.
- **"기기가 따라오는가" 는 소프트웨어로 답할 수 없다 — 그래서 답할 수 있는 것만 쟀다.**
  이미지 푸시에는 ack 가 없어(Studio·기기 모두 무응답, 인바운드는 입력/생명주기뿐) **패널이
  버린 프레임과 그린 프레임이 구분되지 않는다.** 대신 관측 가능한 둘을 실기기에서 측정:
  소켓 송신 큐는 페이싱을 걷어내고 13키 136KB 를 38ms(≈3.6MB/s)에 밀어도 **모든 버스트에서
  0B**, Studio CPU 는 애니 ON/OFF 를 재시작 통제 비교로 돌렸을 때 **차이가 런간 편차보다 작다**
  (ON 1.39/1.31 vs OFF 1.43 CPU-초, 셋 다 2.0s 에 idle 복귀). 즉 GIF 추가 페이로드는 Studio
  시간에 잡히지 않는다. 애초에 정상상태 푸시가 0B/s 라 루프가 올라간 뒤엔 트래픽 자체가 없다.
  수치와 **그 수치가 답하지 못하는 질문**은 `plugin-ulanzi/VERIFY.md` 에 적어 뒀다 — 0B 큐를
  "기기까지 문제없음" 으로 오독하지 않도록. 측정 중 폐기한 무효 계측 둘도 남긴다: Studio 의
  `.xlog` 는 압축이라 기기 쓰기 기록을 못 읽고, 워밍된 Studio 에 플러그인을 직접 붙이는 건
  **Studio 가 자기가 spawn 한 플러그인만 수락**해 실패한다(그때 오른 CPU 는 리페인트가 아니라
  연결 거부다 — 그대로 썼으면 오판이었다).
