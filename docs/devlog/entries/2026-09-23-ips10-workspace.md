# 2026-09-23 — IPS10 task workspace replaces the office and mosaic

Replaced the IPS10 screen hierarchy with a full-display workspace: status totals/filters, an attention-first session rail, persistent selected-task detail, reported child/background counts, two recent events, and an explicit eight-event history. Selection follows session IDs across daemon reorder/removal; unattributed or other-session records never enter a task's history. New task selection resets scroll position. Offline and empty states remain explicit. Unknown census/usage stays unknown, and idle is not treated as completion.

The old IPS10 office is not initialized or animated behind the dashboard. Voice controls move into a separate drawer; the existing wake-word routing and hold-to-talk pipeline remain. Speech recognition verification was explicitly deferred by the user; camera capture/vision was not implemented as part of this UI task.

Primary text now uses the repository's IBM Plex Sans KR at a real 20px, addressing the old 20px wrapper's 16px Hangul fallback. IPS10-only generated 2bpp uncompressed fonts cover ASCII/Hangul plus a 36px digit subset. Generation uses lv_font_conv 1.5.3; arguments are in each generated header, with trailing blank lines normalized. The final firmware uses 5,430,536 / 6,291,456 application bytes and 89,684 bytes static RAM. Reused LVGL widgets and fixed text/snapshot storage keep the update path bounded.

Validation: workspace native interaction suites passed at 1280×800 and 800×1280, including ring wrap, attribution, priority, removal, filters, scroll reset, voice drawer bounds, offline, and empty state. Both orientations were visually inspected and iterated. IPS35's native build and multi-session render passed as a shared-HUD regression check. `pnpm build`, `pnpm typecheck`, and 4,654 tests (305 files; two skipped) passed. Protocol generation left no drift; all seven token mirrors and documentation/catalog checks passed. Design lint retains its pre-existing 92 HTML/JS violations.

Initial USB deployment to the identified IPS10 (P4 rev1.3, 16MB flash) passed write hashes and boot verification. Read-only `workspace_diag` observed four live sessions, 1280×800 geometry, advancing updates, typical state-update processing around 4ms and maximum 10.988ms over the observation. This timing excludes the subsequent display flush. A second deployment includes the typography and scroll corrections; final runtime evidence is recorded below. Native event tests and runtime diagnostics do not constitute a physical finger-touch accuracy test.

Specification: [ESP32 workspace](docs/esp32.md#ips10-task-workspace). Local diagnostic artifacts are retained in the task worktree under `diagnostics/workspace/` (build logs, simulated PNGs, USB logs, filtered runtime snapshots); they are not checked in as generated evidence.

Final deployment: full USB flash hashes verified; the new boot epoch is `1790130054` (initial deployment was `1790129534`). The image SHA-256 is `a7d4c86202948f8e8e1326113d685db9de139e5b7b9feba6a3cb12a2fa3dc491`; it contains the implementation committed as `f194531a` and reports the pre-commit build label `c73db5ed-dirty`. Six sessions refreshed continuously; observed update processing median was 4.370ms, with a 74.648ms maximum including startup (not a display FPS measurement). The serial lease was released and the daemon confirmed a fresh, connected IPS10 at uptime 159s with the new epoch.

The additional physical portrait probe did **not** pass: the existing IPS10 `UI::setOrientation` is a no-op and its flush path is fixed landscape. The device remained at 1280×800 and continued refreshing; no portrait capability is claimed. Both software layouts passed the simulator. This distinction is documented in the specification rather than treating a successful flash as proof of rotation support.
