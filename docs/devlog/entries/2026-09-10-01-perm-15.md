# 2026-09-10 — 유령 PERM: 게이트웨이가 15분 전에 버린 승인을 데크가 들고 있었다

사용자가 "왜 지금 OpenClaw 세션이 PERMIT 인가, 정상인가" 라고 물었고, 답은 **시작은
정상, 물어본 시점은 유령**이었다. 양쪽 로그로 전 과정이 붙는다.

| 시각 | 어디 | 무슨 일 |
| --- | --- | --- |
| 23:14:25 | OpenClaw | glm-5.3 턴이 `find ~/.openclaw/workspace …` 승인 요청 생성 (`de7bf820…`). 레코드 만료 = +30분 = 23:44:25 (`DEFAULT_EXEC_APPROVAL_TIMEOUT_MS = 18e5`) |
| 23:22:03 / 23:23:23 / 23:24:43 | AgentDeck | 데몬 재시작 3회. 매 핸드셰이크마다 `exec.approval.list` 로 정상 재입양 → `tool_request` 3줄(같은 id). 데몬 로그의 `OpenClaw Gateway connected` 시각과 1초 내 일치 |
| **23:29:33** | OpenClaw | `exec.approval.waitDecision` 가 **908,788ms(15분 9초)** 만에 반환, 같은 ms 에 `exec.approval.request ✗ agent runtime authority is no longer active` — 요청한 run 이 죽고 레코드가 치워짐. **`exec.approval.resolved` 는 오지 않는다** |
| 23:29:33→23:44:25 | AgentDeck | **15분간 유령 PERM** |
| 23:40:37 | 사용자 | Allow once → `INVALID_REQUEST: unknown or expired approval id` (양쪽 로그 동일) |
| 23:44:26 | AgentDeck | 레코드 자체 만료 타이머 발화 → `Not approved · Expired`. 스스로 나음 |

게이트웨이에 직접 물은 것도 일치했다: `openclaw exec-approvals pending` → *No pending
approvals*. 같은 모양(`waitDecision` 반환 + `agent runtime authority is no longer
active`)이 로그에 **5회** 있다 — 드문 사고가 아니라 반복되는 형태다.

### 결함 2개

**(A) 실패 한 단어에 두 답을 접었다.** `resolveApproval` 의 catch 는 모든 실패를
"프롬프트를 다시 뿌려 재시도하게" 로 처리했다. 그런데 `unknown or expired approval
id` 는 게이트웨이가 **"그 승인은 이제 없다"** 고 답한 것 — 재시도가 절대 성공할 수
없는 유일한 케이스다. 누를수록 같은 실패가 반복되고 유령이 더 오래 남았다.

**(B) 승인의 수명이 둘인데 긴 쪽만 알았다.** 레코드 만료 30분 vs 기다리는 run 의
수명(오늘 15분 9초). 후자가 끝나면 게이트웨이는 레코드를 조용히 치우고 아무 이벤트도
안 보낸다 → 자기 종료 타이머 하나에 기댄 구조는 **최대 15분 늦다**.

### 고침

- `isApprovalGoneError` (`shared/src/openclaw-approval.ts`) — 게이트웨이 **자신의**
  분류기(`isApprovalStaleError`, 설치된 패키지에서 읽음)의 미러: 구조화된
  `code`/`details.reason` 이 본 채널, 메시지 정규식은 게이트웨이가 스스로 legacy 라고
  부르는 보조 채널. 모르는 모양은 **false** — 잘못된 "gone" 은 에이전트가 아직 막혀
  있는 살아있는 승인을 버리고, 잘못된 "not gone" 은 한 번 더 누르는 값이다.
  생성기로 Swift 미러 emit, `shared/openclaw-approval-error-vectors.json` 을 양 suite
  가 재생. 벡터의 문자열은 전부 게이트웨이 것이지 이 술어에 맞춰 지어낸 게 아니다.
- Node `rpcCall` 의 reject 가 프레임의 `code`/`details` 를 싣는다(전엔 문장만 남고
  구조화된 절반이 버려져 모두가 문장 매칭을 하고 있었다).
- **표시 중인 승인은 30초마다 `exec.approval.list` 로 대조**한다. 읽을 수 있는 답에
  내 id 가 없을 때만 닫는다 — 전송 실패·타임아웃·파싱 불가는 전부 "모름" 이고
  그대로 둔다. 소켓이 닫혀 있으면 묻지도 않는다.
- **Swift 는 Node 보다 나빴다**: 만료도, abandon 도, 연결 끊김 시 정리도 없어서 유령
  PERM 이 **영구**였다(`pendingApproval` 을 지우는 유일한 경로가 오지 않는
  resolved 이벤트). 이제 네 경로 모두에서 정리한다 — gone 에러 / 대조 / 레코드 만료 /
  연결 끊김 — 그리고 데몬은 새 `gateway_approval_abandoned` 이벤트로 캐시된 프롬프트를
  비운다. Swift 의 resolve 도 fire-and-forget 에서 응답을 보는 형태로 바꿨다.

### 검증

- vitest 4,236개 통과(신규 23). `openclaw-approval-flow` 에 gone-에러 abandon /
  전송실패 유지 / 대조 abandon / 아직 pending 이면 유지 / 박스형 `{approvals:[…]}` /
  읽기 불가·실패는 무변화 / 닫힌 소켓엔 질의 안 함을 고정.
- macOS 타깃 빌드 + `OpenClawApprovalErrorTests` 통과(같은 벡터 파일 재생).
- 실기: 데몬 재시작 후 게이트웨이 connected, OpenClaw 행 `idle`, 대기 승인이 없는
  동안 `exec.approval.list` 폴링이 게이트웨이 로그에 **0건**(폴링은 프롬프트가 떠 있는
  동안에만 돈다).
- 유령이 실제로 지워지는 end-to-end 는 재현하지 않았다 — 그러려면 사용자 에이전트에
  진짜 승인 요청을 일으켜야 한다. 대신 부품별로 게이트를 걸었고, 분류기의 문자열은
  설치된 게이트웨이 소스와 이 기계의 로그에서 왔다.
