# 2026-09-02 — 1.2.0 판올림 사전 감사: 죽은 태그의 원인은 그 순간의 장애였고, 검증은 dispatch로 산다

### 문제

1.2.0 라운드가 준비된 상태에서 세 가지 불일치가 남아 있었다. (1)
apple-v1.1.0 태그는 아무 아티팩트도 만들지 못한 죽은 태그 — 릴리스 런
하나는 71시간 큐잉 후 취소, 재푸시는 0초 startup_failure, 워크플로 파일은
1.0.8 성공 이후 무변경이라 원인 불명. (2) plugin-ulanzi는 1.0.5 태그 이후
행동 변경(`daemonConnected` OFFLINE 분리)이 있는데 버전이 그대로 —
같은 버전 두 빌드 드리프트 직전. (3) CHANGELOG ESP32 항목의 "푸터 12pt"가
이후 실기 수정(9pt Bold 2줄)과 모순.

### 해결

- **Apple 실패는 레포 결함이 아니라 8/26 15:34–15:36 GitHub 장애 윈도우**:
  같은 분(15:35:03)에 무관한 Apple Tests도 startup_failure였고 그 전후의
  macOS 런은 전부 성공. 실패한 세 런 모두 job 0개(러너 미배정) — 큐에 그
  순간 들어간 런만 죽거나 좀비가 됐다. 증명은 재현으로: `workflow_dispatch`
  + `upload=false`로 파이프라인을 통째로 드라이런해 validate 29s / iOS
  archive+export+invariants 2m34s / macOS 10m13s 전부 green. **릴리스
  워크플로에 upload 토글이 있으면 "고쳐졌다"는 주장을 태그 없이 측정할 수
  있다.**
- Ulanzi는 1.2.0으로 라운드에 합류(1.0.4 심사 포기 결정 — 심사 기간이 두
  버전을 추월했다), CHANGELOG 12pt 문장은 실기 결과로 교정.
- **로컬 3모드 데몬 검증**: CLI 재시작(9개 모듈·WS 14클라이언트·시리얼
  9보드 복구) → Swift 단독(앱 재빌드 후 fallback 9121에 떴다가
  `failedBindMemorySeconds`=120s 만료 후 9120 자체 회수, pairingToken 수렴
  확인, WiFi 플릿 11대 + 훅 세션 등록) → 양립(CLI가 히스토리 병합 후
  stand-down 협상으로 인수, 앱은 클라이언트 모드, ADB 복귀). 문서에 적힌
  수렴·양보·회수 기계가 전부 실측으로 돌았다.
- 새 Ulanzi 1.2.0 번들을 Studio에 실배포해 D200H 재접속 확인(설치본은
  1.0.3이었다 — 스토어 경로가 막힌 동안 로컬도 두 버전 뒤처져 있었다).

### 교훈

죽은 태그를 볼 때 첫 질문은 "무엇이 바뀌었나"가 아니라 "그 시각에 무엇이
같이 죽었나"다 — 무관한 워크플로의 같은 분 startup_failure 하나가 워크플로
파일 grep 전체보다 빨리 원인을 배제했다.
