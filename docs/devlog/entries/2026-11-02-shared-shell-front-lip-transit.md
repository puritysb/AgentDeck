# 2026-11-02 — Shared shell front-lip transit

The November 1 tablet recording exposed a geometry error that the earlier
home-position tests could not see: after reaching the shell, the renderer
translated the entire mermaid down by `0.65 * size`. Her animated tail crossed
the sealed lower valve before visibility was disabled. A manifold shell asset
cannot hide a character deliberately moved through its underside.

The native motion now follows a reversible route over the front lip, across a
low depth lane, then up into its assigned berth. Return reverses those legs,
then lifts the whole body above the front lip before compaction. A low approach
that passed the world-floor bound still looked like under-shell entry in the
physical portrait recording, so the final mouth rise is separate from the low
travel lane.
Inside the basin, compaction is anchored at the model's measured lowest point;
there is no independent downward translation. The shared lid's actual aperture
holds entry until it clears, and the entrance lease clears the whole resident
before admitting the next. The lid may close while agents remain outside.

Three simultaneous Hermes models revealed a second problem: diagonal travel
between front approach and deeper berths crossed an occupied row. Actual
RealityKit bounds are sampled during this stress case, alongside the grounded
OpenClaw lifetime and the lower-valve floor check. Depth-separated rows and the
low depth leg resolve that case without changing the original creature meshes.
OpenClaw uses gateway availability for first arrival/final departure; an idle
routing state does not send it home.

The visual fixture is loopback-only and separate from the shared daemon. Android
uses the existing `dev.agentdeck.hermespreview` validation package so production
app data and signing identity stay intact. Device captures and verification
receipts carry their own provenance; a model-bound test alone is not a physical
screen inspection.

The full-tier candidate run passed Android and every Apple configuration,
but the ESP32 simulator compile caught removal of the still-used 2D
`HermesHomeDepartureStart`. C++ uses PascalCase generated names; searching only
Swift/Kotlin spellings missed both 2D consumers. Restore that existing threshold
in the SSOT rather than changing the firmware motion. The native motion files
and all other rule values remain byte/value-identical to the passing native
candidate. Retain the failed full receipt alongside the scoped repair evidence;
do not relabel a partial rerun as another complete native test run.
