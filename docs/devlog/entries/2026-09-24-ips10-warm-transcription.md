# 2026-09-24 — Optional warm local Whisper transcription

Device dictation can opt into `voice.whisperServerUrl` while retaining `transcriber: "whisper-cpp"` and the existing absolute CLI/model paths. Only an HTTP `127.0.0.1` URL ending in `/inference`, without credentials, query or fragment, is accepted. Multipart WAV requests carry the configured language, reject redirects and have a five-second deadline. Unavailable, stalled or malformed server responses fall back to the configured local CLI; a valid empty transcript remains no-speech. No server is started implicitly by application code, and Apple transcription remains the default.

On this Mac, an operator-managed launchd service `dev.agentdeck.whisper-local` keeps the existing large-v3-turbo model loaded in `/opt/homebrew/bin/whisper-server`, bound to `127.0.0.1:19121`. Its plist is under the user's `Library/LaunchAgents`, working directory and logs under `.agentdeck/whisper-local`. The explicit endpoint setting is `http://127.0.0.1:19121/inference`. Removing that optional setting returns immediately to per-request CLI operation; booting out this service releases its resident model memory. Service availability and model selection are operator-managed, not inferred from the endpoint. The personal agent/model and firmware are unchanged.

A repeated captured-audio benchmark measured CLI 1.225 / 1.258 s versus warm HTTP 0.522 / 0.482 / 0.473 s with the same large-v3-turbo model and Korean language. This is recognition-stage timing, not total response latency or an accuracy improvement; the existing recording's recognition error remained. Live compiled-module checks cover the warm path and an unavailable endpoint falling back to CLI. Unit tests cover loopback validation, redirect refusal, request deadline, multipart language, empty speech and error fallback. Build/typecheck and 4,674 tests pass (two skipped), protocol generation has no drift and token checks pass; design lint retains the pre-existing built-checkout findings. Hardware deployment measurements follow below.

Deployment: stable-main daemon build `3179cf3a3ac4` was built, restarted through `agentdeck daemon restart`, and verified against its on-disk content identity. The optional endpoint is enabled, and the loopback worker is supervised by launchd (about 1.8 GiB RSS at inspection). Three acoustic hardware round trips all completed, with the same IPS10 firmware epoch `1790184469`: Transcribing-to-Waiting UI intervals 1.214 / 1.011 / 0.692 s, versus the preceding 2.054 / 1.827 / 1.818 s. Endpoint-to-Speaking intervals were 9.953 / 5.584 / 7.734 s; the total includes variable personal-agent work and cannot all be attributed to this change. Uploads returned HTTP 200 on the first attempt and all three replies downloaded/played, returning to wake. The worker log confirms inference requests on the resident model. Diagnostics: `diagnostics/voice-host/hardware.log`. No firmware reflash or personal-model change was needed.
