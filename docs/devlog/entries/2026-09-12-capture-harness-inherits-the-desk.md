# 2026-09-12 — 촬영 하니스가 데스크를 상속한다: 스토어 자산이 조용히 썩은 네 갈래

"마켓 대비 쌓인 변경점 브리핑"에서 시작해 자산 점검으로 넘어갔고, 결국 **촬영 하니스 자체가 네 군데서
기계 상태를 자산 안으로 흘려보내고 있었다**는 결론에 닿았다. 공통점은 하나다 — 넷 다 **픽셀을 열어보기
전까지 어떤 게이트도 잡지 못한다**.

증상의 출발점: App Store 프리뷰 영상 3종에 `inkdeck` 이 그대로 박혀 있었다. 9/8 에 `trmnl_75` 로
리네임했고 오케스트레이터·mock 은 그때 같이 고쳐졌는데, **영상은 7/19 산출물이고 그 뒤로 아무도
하니스를 돌리지 않았다**. 생성물이 소스와 함께 늙지 않는다는 게 이 라운드의 밑바닥 교훈이다.

### 1. `screencapture -V` 는 백킹 해상도로 녹화하지 않는다

같은 5120×2880 패널에서 **정지 캡처는 5120×2880, 동영상은 4096×2304** 로 나온다. macOS 프리뷰의
크롭은 "논리 창 크기 × 2" 하드코딩이었으므로, 실제 비율 1.6 과 어긋나 **프레임의 80% 만 대시보드,
20% 는 배경화면**이었다.

지독한 건 이게 어떤 계측에도 안 걸렸다는 점이다. `force_window_geometry` 는 1856×1044 를 읽어서
통과했고, 인코더는 1920×1080 을 보고했고, `validate-appstore-submission.sh` 도 합격시켰다.
**숫자들은 서로 전부 일치했고 다 같이 파일과 불일치했다.** 크롭은 이제 녹화된 raw 의 실제 크기를
디스플레이의 논리 크기로 나눠 계산하고 로그에 찍는다(`raw 4096x2304 · logical 2560x1440 ·
crop=2970:1670:0:48`).

### 2. 운영자의 UI 상태

대시보드의 Habitat/Collaboration 토글은 `dashboardCollaborationEnabled` 로 영속되고, Debug 빌드는
출시 번들 ID 를 공유한다. 그래서 내가 확인하려고 켜 둔 패널이 다음 촬영에 그대로 들어갔고 —
하필 `05-devices` 크롭의 원본인 토폴로지 레일을 가렸다. 촬영 전에 결정론적 값으로 못박는다.

### 3. 시스템 언어

WeatherKit 귀속 라벨은 로케일을 따른다. 한국어 시스템에서 찍으니 나머지가 전부 영어인 캡처에
**`날씨`** 한 단어가 박혔다 — 런북이 "raw 캡처는 로케일 독립"이라고 주장해 온 바로 그 자리다.
`-AppleLanguages '("en")'` 로 실행해서 ` Weather` 로 고정했다.

### 4. z-order

`screencapture -D` 는 합성된 화면을 찍으므로 대시보드 위에 뜬 창은 무엇이든 크롭 안에 들어온다.
이 데스크에서는 가설이 아니다 — **다른 세션이 빌드 중이던 Godot 창**(`epoch-of-tech`)이 테이크
한가운데로 튀어나와 남의 UI 를 제출 자산에 넣었다. 촬영 동안 다른 일반 앱을 숨겼다 복원한다.
디스플레이·창 원점도 환경변수로 열어서 간섭이 있는 화면을 피할 수 있게 했다. 이때 **창 위치는 전역
좌표인데 크롭 오프셋은 디스플레이 로컬**이라 둘 다 필요하다.

### 정지 컷은 바쁜 데스크에서 살아남고 영상은 못 산다

스크린샷의 각 비트는 순간 포착이라 잠깐의 정적이면 충분하다. 프리뷰는 **48 초 연속**으로 가려지지
않은 화면이 필요하고, 그 사이 다른 세션이 창 하나만 띄워도 건질 게 없다. iOS 는 `simctl` 이
시뮬레이터를 직접 녹화해서 이 문제에서 자유롭다 — 그래서 iPhone/iPad 는 한 번에 성공했고 macOS 만
디스플레이를 옮겨야 했다.

### 촬영 핀에 뚫려 있던 구멍: Collaboration 은 HTTP 로 읽는다

`-AgentDeckScreenshotURL` 핀은 `setPreferredLocalBridge` 를 앞지르도록 설계돼 있다. 이유가 주석에
적혀 있다 — 인프로세스 데몬의 `onReady` 가 앱을 자기 :9120 으로 되돌려 **실제 작업 데이터를 카메라에
올리기** 때문이다. 그런데 Collaboration 패널은 피드를 읽지 않는다. `daemonService.port` 로
`/apme/tasks` 를 **HTTP 로** 가져온다. 결과적으로 나머지 픽셀이 전부 mock 인 프레임에서 그 패널
하나만 개발 데몬을 조회하고 있었다.

두 곳을 메웠다. 데모 오케스트레이터가 소켓 옆에서 그 두 엔드포인트를 응답하고(모양은
`CollaborationModel.swift` 의 디코더에서 읽어 맞췄다 — 클라이언트가 세션 필터를 무시하는 데몬을
거부하므로 필터도 실제로 동작해야 한다), 핀된 피드가 패널이 물어볼 포트를 내준다
(`AgentStateHolder.captureFeedPort`, DEBUG 전용).

### 마케팅과 스토어는 스크립트 레벨에서 갈린다

같은 피드를 쓰되 `--relay-usage` 하나로 갈라진다. Claude 구독 게이지는 샌드박스 빌드가 혼자 만들 수
없으므로(`UsageAPIClient.directOAuthUsageSupported == false`, `TopologyRail.rateLimitChips` 가
`isUsingExternalDaemon` 으로 게이팅) **스토어 자산에 있으면 없는 기능을 광고하는 것**이고, README·
프로젝트 사이트·마켓플레이스는 릴레이가 존재하는 데몬 제품을 설명하므로 **거기서는 진짜**다. App Store
스크립트는 그 플래그를 절대 넘기지 않고, 마케팅 스크립트는 `apple/appstore-submission/` 에 절대 쓰지
않는다.

APME 보드와 메뉴바 활동 요약만은 합성이 불가능하다 — 여기서 스텁한 두 엔드포인트보다 훨씬 넓은 API
를 읽는다. 그 셋은 실촬영이고(`scripts/capture-live-screenshots.sh`), 대신 프레이밍 규칙은 동일하게
적용한다: **1440×900 논리창 → 2880×1800**, 화면이 아니라 창을 크롭. 기존 이미지들은 5120 폭 전체화면
이라 독자에게 필요한 밀도의 1/3 이었고 Dock 까지 프레임에 있었다.

SwiftUI 탭 바는 System Events 합성 클릭을 받지 않는다(확인함). 그래서 그 스크립트는 탭을 조작하는
척하지 않고 선택된 탭을 그대로 찍는다.

### 남은 것

- iPhone 스크린샷은 이 기계에서 못 찍는다. ASC 슬롯이 6.5인치 버킷(1284×2778)만 받고 그건
  "iPhone 14 Plus" 시뮬레이터인데 설치된 14 계열은 14 / 14 Pro / 14 Pro Max 뿐이다. 16 Pro Max 로
  찍으면 1320×2868 이 나와 업로드에서 거부된다 — 런북이 기록한 2026-07-19 사고 그대로다.
- Collaboration 패널의 relation 행(spawned / waiting_on / messaged)은 합성 피드에서 아직 렌더되지
  않는다. 자식 관측(`subagent`)은 나오고 서버가 내주는 JSON 은 클라이언트 필터를 만족하는데 행이
  보이지 않는다. 마케팅 컷의 가치는 이미 확보돼서 더 파지 않았다.
