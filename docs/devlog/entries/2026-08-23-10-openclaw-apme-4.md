# 2026-08-23 — 수정 패스가 결함의 서식지다: OpenClaw APME 리뷰 4라운드

### 문제

#263(OpenClaw APME 구독)을 적대적 리뷰 2종에 걸어놓고 **한쪽 보고가 도착하기 전에 머지했다.**
계약 리뷰어 보고만 보고 그 2건을 고쳐 머지했는데, correctness 리뷰어 보고가 뒤늦게 도착했고
거기에 차단급 5건이 있었다. 영역을 나눠 준 이상 미도착 보고는 곧 **미검토 영역**인데 그것을
"한쪽은 왔으니 됐다"로 처리했다.

가장 무거운 것(B1)은 실측 데이터 손상이었다. `session.message`(assistant)는 **메시지별** 토큰을
싣는데 그 값을 `updateUsage`에 그대로 먹였다. 그 함수는 run 행에 절대 대입하고 ModelEvent 를
`max(0, cur - prev)`로 유도하는 **누적** 계약이고, 유일한 기존 호출자는 PTY 폴러의 누적
스냅샷이었다. 메시지별 값은 단조증가하지 않는다(실측 30302, 21375, 335, 96, 114) → run 행이
**52,222 토큰 쓴 세션에 114** 로 남고, 감소마다 델타가 0 으로 잘려 대부분 ModelEvent 가 붙지
않았으며, `recomputeSampleCost` 가 살아남은 것으로 비용을 매겼다.

### 해결

라운드별로 고치고 **매번 재리뷰**했다. 결과가 이 항목의 요점이다:

| 라운드 | 대상 | 결함 |
|---|---|---|
| 1 | 원 PR | 5 |
| 2 | **1라운드의 수정** | 3 — 그중 1건은 수정이 만든 것 |
| 3 | 2라운드의 수정 | 0 차단급 (하위 영향 1) |
| 4 | 3라운드의 수정 | 0 차단급 (규약 위반 1) |

### 핵심 설계 결정

**가드를 추가하는 수정은 새 가드가 지키려는 대상과 같은 실패 모드를 갖는지 확인해야 한다.**
B1 을 고치며 넣은 `addUsageIncrement` 가 비용 누산기를 `updateUsage` 의 `!runId` 가드 **밖에서**
전진시켰다. 토큰은 버려지는데 비용은 이미 지나간 뒤라, run 열리기 전 스팬 2개 + 후 1개가
**7 토큰에 $10.50**(21배)으로 기록됐다. 수정 이전엔 불가능했던 결함이다 — 누산기가 하나였고
가드 안에 있었으니까.

**한 컬럼이 두 가지를 뜻하게 되면, 뭉개는 것은 못 막아도 그 값으로 순위를 매기는 것은 막을 수
있다.** per-message 비용 기록으로 glm 그룹의 `runs.cost_usd` 가 전부 NULL → 전부 0 이 됐고
(그 provider 는 모든 메시지에 `cost.total = 0` 을 답한다), `cost_per_quality` 가 `?? Infinity`
정렬에서 **"맨 뒤, 절대 추천 안 됨" → "맨 앞, 최우선"** 으로 뒤집혔다. `apme recommend --budget 3`
이 **가격표가 없다는 이유만으로** 계측이 가장 부실한 모델을 최고 가성비로 답할 수 있었다.
컬럼에 "왜 0인지"를 담을 자리가 없는 것은 어쩔 수 없으므로, 0 을 NULL 과 함께 뒤로 보냈다.

**발행을 게이트한 테스트가 소비를 게이트하지 않는다.** `turn_end` span 의 **발행**을 되돌리면
red 인데, collector 의 `closeTurn` 을 되돌리면 2417개 전부 green 이었다. 되돌린 쪽이 하중을 받는
절반이다 — `turns.end_source` 를 쓰는 코드이고, 그 칼럼은 "누락된 close 는 정상 close 와 바이트
동일해서 측정 불가"라서 존재한다.

**의심 목록을 리뷰 프롬프트에 명시하면 실측으로 답이 온다.** "이게 발화하지 않으면 내 수정이
원래 결함보다 나쁘다"고 적어 보낸 `child.once('exit')`(detached+unref)를 리뷰어가 동일 형태로
재현해 측정했다. 추론으로 넘겼으면 20초 실패를 180초 행으로 바꿔놓고 몰랐을 것이다.

**이빨 없는 테스트는 지우지 말고 정직하게 표기한다.** 새 Swift 테스트 하나가 수정 전후 모두
통과했다(수정 전 코드도 phase 를 그대로 반환해 `"error"` 를 냈다). 커버리지로 오독되지 않게
파일 안에 "게이트가 아니라 계약 핀"이라고 적고, 실제로 red 가 나는 게이트는 Node 쪽에 달았다.

### 남은 것

`chat.final` 과 `session.message`(assistant) 중 무엇이 나중에 도착하는지는 **코드 추론일 뿐
실측이 아니다** — 8,000자 잘린 투영본이 원본 응답을 덮어쓸 수 있고, 소유자를 정하려면 라이브
Gateway 캡처가 필요하다. per-turn model 은 여전히 `updateModel` 로 run-level 에 기록된다
(emitter 자기 주석이 버그라 부르는 그것, `turns` 칼럼이 필요). `gen_ai.system`(provider)은
발행되지만 소비자가 없다. `expectedCostUsd` 는 미가격 모델에 아직 `0` 을 API 로 내보낸다
(와이어 타입이라 protocol 재생성 + Swift/Kotlin 미러 동반).
