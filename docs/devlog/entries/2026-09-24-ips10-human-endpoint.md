# 2026-09-24 — Give IPS10 human speech time to finish

The user reports both wake-only submissions and commands cut off mid-sentence. Earlier synthetic round trips and the user's confirmation of intact reply onset did not validate conversational endpointing. The 180 ms cue exclusion was shorter than the new 80 ms playback priming plus 120 ms cue, before DMA/room echo. The 700 ms silence deadline was also too aggressive for conversational pauses.

The endpoint now ignores energy while the actual speaker is active and for 200 ms afterwards, with an initial 450 ms wake-tail guard. It requires 160 ms sustained sound to establish a command, allows 1,200 ms silence between words, and waits 6 seconds for the first command. Recording still retains all samples, including speech overlapping the cue; this change only gates endpoint evidence. Existing first-syllable playback protection remains intact. This is energy-based endpointing, not semantic VAD: short commands entirely overlapping the guard and long pauses remain limitations requiring human evaluation.
