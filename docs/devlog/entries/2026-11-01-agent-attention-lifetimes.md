# 2026-11-01 — Attention needs both a human-wait source and a closing boundary

The earlier [agent audit](docs/devlog/entries/2026-10-25-agent-attention-audit.md) removed speculative approval sources. That did not make every producer's lifetime equivalent: Node Claude had terminal roster tombstones but its overlay accepted late notifications; Swift could synthesize a Claude row from a notification after SessionEnd, and retained an awaiting row for six hours if SessionEnd was lost. The OpenCode PID fix did not cover Claude's hook-only Swift producer.

Claude now rejects a delayed permission notification after an observed Stop until a new prompt/tool opening, and rejects post-SessionEnd callbacks until SessionStart. Unknown sessions remain admissible after daemon restart; ordinary idle/background notifications after Stop still pass. The admission policy and bound live in the existing Claude permission SSOT and its generated Swift mirror. Swift also uses the hook's owner PID for Claude eviction; PID eviction requires confirmed process death, while unavailable process evidence retains the existing lifetime.

OpenClaw had two additional holes on both daemon tiers: an explicitly expired request could be displayed before its timer/sweep ran, and a successful resolve RPC relied on a separate resolution push to settle the displayed state. Expired requests are now rejected before publication, catch-up skips expired rows before choosing the oldest live request, and successful RPC answers use the normal resolution path for that exact request. Network failures retain pending requests; a newer concurrent request cannot be cleared by an old RPC completion.

Hermes has explicit opening/stop/end admission and three-answer process eviction; Kiro's transcript reducer emits only idle/processing; Antigravity has no permission-wait producer. None infers Attention from tool commands or text. This is not support for detecting those agents' real permission dialogs. Legacy managed PTYs still depend on rendered prompts and cannot distinguish an identical printed example; no new managed parser is introduced.

Dot preview is a separate reported-activity surface, not an awaiting session or approval dialog. Its explicit `needs_attention` report is bounded by request expiry and report freshness; delivery/app presence cannot create reported work, and completed/stopped hosting does not retain an active attention phase. Existing `DotDirectHostingTests.testCompanionNeverInfersWorkFromDeliveryOrAppPresence` covers those phase boundaries. Historical result cards are informational and do not block Dashboard navigation.

The Dashboard's shared Attention layer already respects the independent aquarium-view toggle and alive roster filter. Its background handler and viewing-mode control have no agent-specific approval gate. Hiding the HUD does not answer, cancel or discard a real request. The earlier local UI acceptance applies to that unchanged common control path; this audit does not claim fresh interactive approval acceptance for every installed agent or physical device.
