# 2026-11-01 — An abandoned OpenCode acceptance fixture blocked Dashboard navigation

The reported row `agentdeck-device-acceptance-phone-V2jgCD` came from a separate checkout's developer fixture. Its private OpenCode configuration explicitly set `bash: ask`; the harmless `agentdeck_device_acceptance_probe` command therefore really waited for permission. At inspection both the fixture orchestrator and its OpenCode child were still alive. The foreground user task ending had not stopped that detached test. The screenshot was not evidence that ordinary Bash execution should trigger Attention.

Stopped only the identified phone fixture, confirmed its child exited, then delivered that exact session's end to the daemon. The live Dashboard lost the OpenCode card. No permission was granted and no command was approved. The running fixture was stopped without modifying its owning checkout. Its source was subsequently integrated into main by the parallel device-acceptance work.

Two product gaps amplified the abandoned test: the observer omitted its process identity, so death without a final hook could leave an approval for the 30-minute hook TTL; and MonitorScreen deliberately removed background navigation whenever any session awaited input. The observer now sends its own PID, both daemons retire a row only on confirmed owner exit (probe failure remains unknown), and Dashboard viewing mode remains independent of Attention. Hiding the HUD never answers the pending request; showing it restores the prompt. An explicit accessible viewing-mode button also avoids depending on a RealityKit background hit.

The isolated daemon E2E starts a real owner process, presents its permission wait, kills only that process without Stop/SessionEnd, and asserts the row disappears. Unit cases preserve unknown probes and legacy missing-PID sessions and cover delayed callbacks and resumed owners. The real user Dashboard is never used as the hook receiver for these regression fixtures.

The final integration includes main’s native OpenCode permission choices and request correlation. Its relay E2E now establishes a live observer poll before answering; an unpolled observer is intentionally not answerable. The tracked developer fixture now defaults to a three-minute deadline, permits an explicit bounded timeout override, and kills its child on parent exit. A fake child (no observer plugin, no production hooks) covers both deadline and parent-signal cleanup.

Before integration into local main, the final `7bd02eb`-based source passed quick (7,101 tests), coverage floors, all 39 daemon E2E cases, and all five Apple configurations. CloudKit macOS/iOS, submission limits and clean npm package acceptance passed in a complementary full-tier run. Unchanged Android and ESP32 gates passed in the earlier run. The committed full-tier receipt is the scoped coverage/documentation rerun after an unrelated resource-read test exceeded its deadline under concurrent compiler load; it does not claim that four recorded steps alone cover every platform. A fresh catalog/native-palette/fixture check passed all 20 cases after staging the new test file.
