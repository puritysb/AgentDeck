# Native attention observation

합성 브라우저 실험의 다음 단계입니다. **실제 세션을 읽는 SwiftUI 패널**을 만들고,
동일한 소스 파일을 제품 메뉴바와 별도 관찰 창에서 공유합니다.

## 현재 적용 범위

- 제품: 메뉴바의 톱니바퀴 → `Attention context (experimental)`으로 오른쪽 Activity 영역을 교체합니다. 기본값은 꺼짐입니다. 테라리움·기존 응답 컨트롤·데몬·프로토콜은 바꾸지 않습니다.
- 첫 사용: 기존 앱 교체 없이 별도 `AttentionObservation.app`을 실행합니다. `master`의 다른 Apple/데몬 변경이 아직 미커밋인 상태여서, 이전 기준의 앱으로 이를 덮어쓰지 않기 위한 임시 검증 표면입니다.
- 입력: loopback의 `dashboard-live/v1`, `sessions.read`만 요청합니다. 앱 코드의 유일한 outbound 메시지는 `client_register`이며 focus/승인/옵션/프롬프트 명령은 없습니다. 협상하지 않는 구형 데몬에서도 읽기 baseline만 소비합니다.
- 저장: 세션·질문·관측 이력·평가를 파일이나 외부 서비스에 기록하지 않습니다. 선택은 창의 메모리에만 있고, 제품의 켜기/끄기 설정만 기존 UserDefaults에 남습니다.
- 한계: 세션 목록에 활동 요약이 없으면 그렇게 표시합니다. 타임라인 원문을 추가로 수집하지 않습니다. 개별 훅 출처·요청 만료 시각이 없는 데이터로 이를 추정하지 않습니다. 이 첫 버전은 새 응답 도착을 탐지하는 기능이 아닙니다.

## 실행과 종료

macOS + Xcode Command Line Tools + Node.js 22 이상이 필요합니다.
저장소 루트에서 다음을 실행합니다. 기존 관찰 창이 있다면 먼저 종료하세요.

```sh
bash experiments/attention-lab/native/build.sh
open experiments/attention-lab/native/build/AttentionObservation.app
```

빌더는 사용자 자신의 daemon registry에 적힌 포트와 `/health`의 PID를 확인합니다.
그 데몬이 없으면 실패하며 포트를 스캔하거나 데몬을 시작하지 않습니다.
빌드 폴더의 앱에만 포트·로컬 폰트 경로를 넣습니다. 포트가 바뀌면 다시 빌드하세요.
이것은 로컬 개발 도구이며 배포/업데이트 채널이 아닙니다.

창을 닫으면 WebSocket 관측이 종료됩니다. 앱을 완전히 종료하려면 Cmd+Q.
연결 끊김/20초 목록 미수신 때 마지막 맥락을 유지하며, `다시 연결`은 이 관찰 창의 소켓만 재연결합니다.

## 사용하면서 볼 세 가지

1. **찾기:** 사람이 필요한 세션을 찾기 쉬운가? 같은 프로젝트의 여러 세션을 구별할 수 있는가?
2. **맥락:** 원래 화면으로 돌아가기 전에 충분히 알 수 있는가? 활동 요약 부재·긴 ID·문구가 방해되는가?
3. **방해:** 새 상태가 와도 읽던 대상이 유지되는가? 선택해서 상세로 이동하는 것과 자동 화면 이동을 혼동하지 않는가?

첫 3~5번의 실제 개입에서 `상황 / 도움이 된 정보 / 부족하거나 오해한 정보 / 원래 화면으로 돌아간 이유`를 짧게 알려주세요.
실제 요청 원문이나 세션 ID를 기록할 필요는 없습니다. 우선 수동 관찰로 평가하고,
자동 계측·알림·원문 저장은 필요성이 확인된 뒤 별도로 결정합니다.

## 검증

빌드 시 실제 제품과 공유하는 순수 모델에 대해 19개 검사를 실행합니다.
새 대기의 선택/순서 비개입, 연결 끊김의 맥락 보존, 사라진 대상 유지,
재선택, 중복 ID/프로젝트명, 미지 상태와 capability 부재를 확인합니다.
제품 통합은 별도 DerivedData에서 macOS Release를 빌드하며 기존 앱을 실행하지 않습니다.
기존 네이티브 팝오버 안의 실제 레이아웃 QA와 사용자 사용성 평가는 아직 별도 단계입니다.

최종 소스의 macOS Release 빌드와 `verify-appstore-archive.sh`를 통과했습니다.
이는 제품에 선언된 entitlement를 사용한 **로컬 ad-hoc 서명 검증**으로,
배포 서명·App Store 제출 검증이나 기존 앱 교체를 뜻하지 않습니다.
별도 관찰 앱에서 실제 roster 수신·세션 선택·맥락 상단 이동·재연결·선택 대상 소멸 시
마지막 맥락 보존을 확인했습니다. 기존 브라우저 모델/서버 테스트 11개와 문서 검사도 통과했습니다.
