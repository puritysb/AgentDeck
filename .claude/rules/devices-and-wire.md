# Wire contract and device surfaces
<!-- Moved verbatim from CLAUDE.md (2026-09-10). Rule bodies are the SSOT for their domain; CLAUDE.md keeps only the map. -->
Rules every surface (TS/Swift/Kotlin/C++) must agree on: optional-field merging, integer stamps, unknown agent
types, timeline dedup, device-keyed work, deterministic renderers, and the Ulanzi/BLE packaging traps. The
cross-platform SSOT catalogue is [docs/architecture.md](../../docs/architecture.md).

## Surface boundary and cached contexts

- **External Surface boundary**: `shared/src/protocol.ts` remains the complete internal implementation wire for first-party clients; it is not exported wholesale as a third-party contract. Independent dashboards, controls, readers, and panels target one allow-listed profile in `docs/surface-protocol.md` (`dashboard-live/v1`, `companion-control/v1`, `portable-reader/v1`, `display-only/v1`) and publish an `agentdeck-surface.json` manifest. Profile/capability additions stay additive, control fails closed, and firmware OTA identity is the full `productId + board + updateChannel` tuple — a board string identifies hardware, never product ownership. Existing official apps/firmware retain wire compatibility; a Surface contract change must not require them to update in lockstep
- **Weather is a cached Surface context, not a live API passthrough**: both public daemons normalize keyless MET Norway data into `CardFeedGlance.weather` (identify the app, obey `Expires`/`Last-Modified`, persist the cache). The Swift app may additionally use native WeatherKit for its own Dashboard, with the required Apple mark/legal link and only an in-memory refresh cache; Apple Weather data is never the portable feed or seven-day persisted cache. The public shape keeps current/today/tomorrow for old firmware and additively carries at most seven days plus eight daemon-authored absolute-time cues. Offline clients persist the MET snapshot, deduplicate cues by `(id,revision)`, never notify after `expiresAt`, and stop presenting forecast after `validUntil`. Probability is optional — never invent it when a provider only supplies precipitation amount. Provider attribution travels with the cache. Location is explicit/coarse and never IP-derived

## Wire semantics

- **Wire booleans carry both signals**: in an optional-field protocol where clients merge **retain-on-absent** (`s.x = e.x ?? s.x`), an omitted key means "no information" — so a flag that is only ever sent when `true` can be set but never retracted, and it latches one-way. Never fold the falsy case into an omitted key (`x || undefined`, `x ? true : undefined`); emit the explicit `false`. This bit `usageStale` twice in opposite directions: 2026-07-17 added only the positive signal (no quota numbers ⇒ `true`, so a roaming dashboard purges foreign quota), and the missing negative signal then pinned the macOS Dashboard's "stale" badge over live percentages until relaunch (2026-07-25). Producers: `bridge/src/usage-event.ts`, `DaemonServer.buildUsageEvent`. Client rule when a legacy producer may still omit the key — **explicit flag > data presence > retain**, never data-presence as a peer of the flag, since "had data, now stale" legitimately ships numbers alongside `true` (`AgentStateHolder.mergedUsageStale`, `shared/src/d200h-layout.ts` `usageKnown`)
- **An epoch-ms stamp on the wire is an INTEGER, and a strict client refuses a frame, not a field.** These stamps are held internally as `Double` (`Date().timeIntervalSince1970 * 1000`), and serializing one straight out puts `1788214664925.6821` on the wire. Kotlin declares such fields `Long` and kotlinx refuses a fractional number for one — and because a census or entry rides INSIDE a larger object, that refusal fails the whole `List<SessionInfo>` decode rather than dropping the field: `parseBridgeMessage` returns null and the frame is discarded. One session with a finished subagent blanked the Android session roster, the header count and every terrarium creature at once, logged only as a truncated `Unparsed WS message` (2026-09-01: 242 consecutive `sessions_list` frames rejected while the timeline beside it rendered normally). Fix at BOTH ends and neither alone: readers stay lenient because devices already in the field cannot be updated (`FlexibleLongSerializer`), and the producer stops emitting the shape so the next client does not have to learn this separately. Producer SSOT `DaemonServer.wireEpochMs`, which **guards rather than casts** — `Int(Double)` traps on NaN and infinity, and a daemon that crashes on a malformed stamp is worse than one emitting a wrong-but-finite number. The Node daemon is unaffected (`Date.now` is integral in JS). Assert such a rule against the **serialized JSON**, never the in-memory value (`1788215929418.0` is a perfectly equal Double and the whole question is what lands on the wire), and capture the fixture off a live daemon — a fixture built from the decoder's own field list agrees with it forever.
- **An unknown `agentType` renders as nothing or as a neutral default — never as another agent.** The daemon and each dashboard/device renderer ship on their own schedules, so every surface WILL receive agent types it predates. Both apps carry `agentType` as `String?` and ESP32 falls back to the raw id, so there is no hard failure — the generated `ADAgentType`/`AgentType` enums are strict (Kotlin's `fromValue` throws) but have **zero uses outside the generated files**, and that is the only reason nothing decodes through them. The real trap is the POLARITY of each fallback: a bucket spelled as a deny-list (`agentType != "openclaw" && != "codex-cli" && …`) silently dresses every future agent as the bucket's owner, which is a *wrong* view, not a degraded one — that is how Kiro sessions swam as Claude octopuses, and how the TUI handed them Claude's glyph and the Stream Deck slot OpenCode's palette. Write allow-lists (`isOctopusAgent` / `isOctopusAgentType`, mirroring `CODING_AGENTS` in `bridge/src/pixoo/pixoo-renderer.ts`, which had it right first). Gates pin the polarity, not the membership, so adding a real agent needs no test edit: `apple/AgentDeckTests/UnknownAgentForwardCompatTests.swift` + the unknown-agent cases in `bridge/src/__tests__/pixoo-creature-sync.test.ts`, including the reverse guard that every wire agent has its own colour and label
- **A back-dated insert defeats a one-sided time window.** The timeline's exact dedup (`deduplicateEntry` step 2) bounded its 8-second window with `if (entry.ts - e.ts > 8_000) break`, which is only ever true for entries OLDER than the incoming one — the direction a live append produces. The turn watchdog inserts the other direction: a `chat_end` stamped at the orphan turn's own timestamp, so the entire newer tail of the buffer was compared against it with no window at all. Every orphan close renders as the byte-identical `Interrupted · –`, so one earlier close anywhere in the buffer made the new one a "duplicate" — it was skipped, the orphan `chat_start` was never paired, and the 60 s watchdog re-reaped the same row **10,603 times over 17 days** while the turn spun "in progress" on every surface. The window is `|Δ|` now, and a turn-close is additionally identified by the turn it closes (`startedAt`), because two different turns closing with the same text are not duplicates of each other — the same reason step 3 already exempted them from the 1 h repetitive dedup.

## Device surfaces and renderers

- **Pending device work keys on the device, not on its socket**: a board is routinely reachable over both USB serial and WiFi, and it **closes its WebSocket when serial becomes primary** (firmware radio-parking). So any daemon state that outlives one request — a queued reply, a deferred push — must be keyed by the board (`device_info.board`) and have its transport **re-resolved at use time** (serial first, mirroring the single-path dedup), never held against the socket it arrived on. Two corollaries, both learned the hard way on the voice reply (2026-07-26): a sweep must expire on age alone (a link that blinks mid-turn is not a dead device — check liveness where you send, not where you sweep), and **capability lookups must not read a registry that dedup deliberately skips** (a serial-attached board is absent from the WiFi registry, so `capabilities` read from there made `audio_out` vanish and the feature silently no-op'd). Remember each socket's own `device_info` report instead. Ref: `bridge/src/device-voice-reply.ts` (`ReplySink.deviceKey` + `resolveLive`)
- **A baked animation loop must close, and only the baked surface can tell you it doesn't.** A live ticker (Stream Deck: `animFrame++` every 150ms) hides incommensurate periods forever, because it never wraps. Bake the same renderer into a looping GIF — which is what the D200H does, since Ulanzi Studio loops it on the device, so a transition costs one push and steady-state motion costs nothing — and every animated value must return to its start at the same frame or the tile visibly jumps once per loop. `SESSION_SLOT_ANIM_CYCLE` (`shared/src/svg-renderers/session-slot-renderer.ts`) is that period; a new animated element must have a period that divides it (dash phase closes at `BORDER_PERIMETER / speed`, so speeds must be one value or integer multiples of it; pulses ride `PULSE_OMEGA = π / cycle`). Two corollaries: **a renderer's output is used as identity, so it must be deterministic** — `svgFrame` minted its gradient id with `Math.random()`, which looked perfect on screen while breaking device push dedup, the "does this tile animate?" probe and the GIF cache at once (never `Math.random()` in a renderer); and **the frame rotation that gives each key its own phase must have exactly one definition** (`frameOrderFor`) — deriving it separately for "collect the frames" and "is this tile still current?" made every phase-shifted key read as permanently stale, so its encode was cancelled and requeued forever, and the symptom was merely "nothing animates". Gates: `shared/src/__tests__/session-slot-anim.test.ts`, `plugin-ulanzi/src/__tests__/anim-schedule.test.ts`, plus the `SYNC-HASH` pin in `apple/AgentDeck/Rendering/SessionSlotRenderer.swift`.
**Dot-matrix brand assets:** Pixoo64/iDotMatrix use the generated 24×24 alpha masks, the legacy Timebox beacon uses generated 9×9 masks, and TC001 uses generated 8×8 masks emitted by `pnpm generate-micro-glyphs` from `design/brand/*.svg`. Node, Swift, and ESP32 consumers may add device-specific color, shading, pulse, rails, and particles, but must not replace those masks with hand-drawn agent geometry. Regression tests preserve each official mark's defining negative space. The current Timebox face is original eye/face geometry, not a provider mark; iDotMatrix defaults to numeric fleet information with event-only official-creature scenes. Both runtimes consume the matrix-expression policy and generated artwork (see docs/devices.md). Pixoo64's 64×64 usage HUD identifies Claude/Codex rows with 9×7 silhouettes sampled from those same official masks and gives both the same provider-row grammar: primary/5h and secondary/7d percentage fills plus reset countdowns; do not reintroduce letter keys or provider-specific standalone rails there.

## Ulanzi plugin packaging

- **plugin-ulanzi/** — Ulanzi Studio plugin for the D200H Deck Dock and D200X LCD keys (official UlanziDeckPlugin-SDK). One dynamic keypad action + session-centric two-level UX, sharing the `@agentdeck/shared` `buildSessionDeck` layout engine. D200X encoders are a separate, not-yet-shipped action/UX; keypad support must not imply encoder support. Connects to the daemon over WS like the SD plugin and is the **sole** Ulanzi deck driver — the Node/Swift direct-HID paths and the legacy `zkswe/` research tree are gone. The Studio handshake does not identify D200H versus D200X, so the daemon preserves the historical `d200h` health wire identity and reports connectivity from `ulanzi-plugin` WS presence. **The Marketplace bundle ships NO native binary, and that is enforced at package time, not intended.** `@resvg/resvg-js` needs one `.node` per architecture, so a single bundle that must run everywhere carried five (18.5 MB of a 20 MB plugin, four unusable on any given machine) and macOS raised "Apple could not verify". Signing was never the fix: a loose native module inside a folder Studio downloads and unpacks has no owner who can sign it for the process that loads it. `@resvg/resvg-wasm` is the same resvg version and Rust core (**pin the two in lockstep** — the identity is the whole argument), ships as one file identical on every OS/CPU, and renders byte-identically (measured over 34 tiles spanning both raster sizes, every session state and `feGaussianBlur`). Three consequences: `initWasm` is async while every tile render is sync, so `app.ts` awaits `initRaster()` **before the Studio bridge opens**, i.e. before any `onAdd` can ask for a key image; fonts became load-bearing, since the WASM build has no filesystem and therefore no `loadSystemFonts` fallback, so a bundle missing them renders every tile textless; and the packaging verify walks the **tree** for `.node`/`.dylib`/`.so`/`.dll` rather than checking package names, so a dependency that grows an optional native accelerator later cannot slip one back in. See [plugin-ulanzi/VERIFY.md](../../plugin-ulanzi/VERIFY.md)

## BLE workers

- **"The OS killed this" is not "this failed", and a dependency probe cannot see an architecture.** Both rules govern the daemon-managed Python BLE workers (`bridge/src/ble-sync-spawn.ts`, `python-ble-runtime.ts`), and each hid the other for two days (2026-08-20: 77 crash reports). A macOS **TCC Bluetooth grant for an unbundled binary is pinned to an exact path**, so a `brew upgrade` or a Claude Code auto-update silently revokes it — and an interpreter with no bundle cannot prompt, it is killed outright with SIGABRT. A backoff respawn re-rolls that kill every period forever, which is amplification, not recovery, so `createSigabrtCircuitBreaker` halts after 3 consecutive SIGABRT exits and names the fix, while any clean exit (a powered-off panel's `device not found`) resets the streak. Separately, a translated interpreter imports `bleak`/`PIL` perfectly, so `dependencyProbe` accepts exactly the Rosetta venv that must be rebuilt: architecture is read from the **Mach-O header** (thin and fat), an x86_64-only python on an arm64 Mac is refused, `ensureBleRuntime` **removes** such a venv before recreating it (re-`venv` keeps wrong-arch native wheels in site-packages), and `/opt/homebrew/bin/python3` is probed ahead of PATH `python3` because daemon-spawned shells resolve `/usr/local` first. Unknown formats (a shell wrapper, ELF, a truncated file) make **no claim** — refuse only when an x86_64 slice is present and an arm64 one is not. Diagnostic rule this came from: a `.ips` crash report is JSON from its second line, and `termination.details` states the reason in a sentence — read it before inferring anything from the stack.
